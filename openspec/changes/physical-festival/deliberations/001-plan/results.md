# Deliberation Summary

## Context
- **Task**: Synthesize the physical-festival implementation plan before runtime work.
- **Personas Consulted**: Architect, Adversary, Profiler + Mediator
- **Date**: 2026-10-29
- **Mode**: Tier 3 synthesis; all three positions were received, with no Round 2.
- **Evidence scope**: Documentation and source-backed reviewer findings only. Runtime and device acceptance remain unrun.

## Synthesized Plan

### Change Group 1: Contract amendments and production verification prerequisites
**Scope**: Resolve integration and ownership contracts before runtime edits, then establish the production-backed fixture. These changes refine the existing plan rather than replacing its task sequence.
**Estimated Effort**: Medium planning effort plus a substantial harness slice; numerical scheduling estimates await implementation discovery.
**Tasks**:
1. **Define one accepted-frame contract.** Adopt a late contact-barrier integration as the proposed default: retain existing cart, people, collection and streaming slots; sample same-frame star eligibility; reconcile authoritative legacy nonphysical cart correction; step physical contacts from accepted cart history; drain mandatory events and claim transitions; republish only affected registry/socket/person state; then interpolate presentation. Ordinary adult steering may consume the last completed physical pose until the next scheduled update, and that deliberate delay must be documented and tested. Do not rerun ordinary activities or add a second people scheduler. Specify substep trajectory interpolation, zero-step behavior, ghost exit separation, and bounded controller feedback without a second positional response. Authoritative queries use solved state; attached sitters/cups share their support's presentation transform. Distinguish hidden-but-ticking frames, genuine suspension gaps, Passport pause and capture/input locks using the existing accepted gameplay clock. **Mapping:** Task 2.2 (Fixed-step clock), Task 2.5 (Cart proxy and resets), Task 4.2 (Single response owner), design Decisions 2, 3 and 6, and the physical-interaction-harness delta. **Acceptance:** an ordered frame table and trace assertions cover 0/1/multiple substeps, moving spatial cells, wall-plus-chair contact and same-frame star pickup without reordered scoring. The late-barrier choice is a proposed implementation contract, not runtime proof. Sources: [Architect structural risks](council-architect.md#structural-risks-identified), [Adversary vulnerabilities](council-adversary.md#vulnerabilities-found), and `ARCHITECTURE.md:898-913`.
2. **Separate canonical generation clearance from live avoidance.** Preserve existing procedural blockers and their established ordering while publishing displaced footprints for runtime queries. Newly added signs and displaced props must not change old builder rejection decisions or downstream RNG consumption. Define a runtime reconciliation operation for a displaced body meeting a newly loaded canonical solid, including overlap detection, valid support and bounded separation without visible reset or duplicate collision authority; hold optional admission when safe reconciliation is unavailable. **Mapping:** Task 3.3 (Registry synchronization), Task 3.5 (World-owner adapters), Task 9.2 (Pure sign intent planner), design Decisions 4 and 11, and registry-collision/physical-props deltas. **Acceptance:** identical seed/load order with different displacement and sign-install timing preserves preexisting descriptors and RNG results. Exploration-order behavior is compared against the existing baseline separately, without claiming global order independence. Source: [Adversary generation-clearance finding](council-adversary.md#vulnerabilities-found).
3. **Make capacity cover transitions, work and metadata.** Reserve body, collider and render capacity for the maximum mandatory person/cup releases when admitting supported assemblies; optional transfers may roll back only while their source remains valid. Optional contents cannot consume that reserve. Account for dormant records, suppression manifests and retained visit state in one bounded ownership policy: live adopted objects retain suppression, while eligible record eviction removes matching suppression coherently. Reconstruct unchanged dormant props from deterministic descriptors. Specify per-frame creation quotas, bounded queued admissions, shared streaming allowance, bounded construction units, prewarming and missing-support behavior. Bound contact-event storage and processing separately, preserving mandatory claim/support/penalty events while cosmetic events may coalesce or drop. **Mapping:** Task 2.4 (Admission and residency), Task 2.6 (Early device gate), Task 3.6 (Visit state and frontier), Task 3.7 (Lifecycle stress gate), design Decisions 2, 5, 6, 8 and 10, and physical-props/drink-props/person-reaction deltas. **Acceptance:** explicit configurable provisional limits, reserved-liability counters and overflow policies exist before engine proof; final numbers remain device outputs. Sources: [Profiler required refinements](council-profiler.md#required-plan-refinements), [Architect metadata finding](council-architect.md#structural-risks-identified), [Adversary saturation finding](council-adversary.md#vulnerabilities-found).
4. **Choose occupied-resource transfer and sign-evidence ownership.** Use a synchronous prepared transfer through the camp adapter into a reaction-owned support resource before origin removal. Preparation acquires a validated support token replacing the campsite entry/slot claim and validates activity generation; commit moves each sitter's claim and supported load once, then invalidates old ownership. Failed preparation preserves a still-valid source; unavoidable support removal uses the reserved release path. Keep token/slot identity guards and population lifetime ownership, and do not retain a whole camp for one chair. Separately, the world-placement adapter supplies sign access evidence keyed by destination and world epoch with unknown/accepted/rejected states. Unknown evidence publishes no unproven blade; unloading alone never means rejection. Resolve unknowns through deterministic placement/access validation rather than waiting for incidental player visitation, with bounded graph queries and count/byte-limited caches invalidated by epoch. **Mapping:** Task 3.5 (World-owner adapters), Task 5.1 (Reaction activity boundary), Task 9.1 (Route evidence survey), Task 9.3 (Next-hop and built-target truth), design Decisions 1, 6 and 9, and crowd-ai/person-reaction/wayfinding deltas. **Acceptance:** the plan defines prepare/commit/rollback/release and validation state transitions, including camp music and two independent loveseat slots. Sources: [Architect adoption and sign findings](council-architect.md#structural-risks-identified), [Adversary occupied adoption finding](council-adversary.md#vulnerabilities-found), [Profiler sign limits](council-profiler.md#required-plan-refinements).
5. **Build the smallest production-backed measurement surface.** Implement existing Task 1.1 (Baseline and compatibility) through Task 1.5 (Baseline scenes), adding the counters and traces above before feature expansion. Use normal Vite imports and register the new entry page in Vite configuration. Keep session ownership, hard timeouts, finally cleanup and exact-PID assertions structural; do not use the prohibited layout capture path. **Acceptance:** repeatable baseline inputs, model/controller/people adapters, reset and teardown work without substituting a toy implementation. Sources: [existing foundation tasks](../../tasks.md#1-establish-source-baseline-and-the-interaction-playground), [verification harness ownership](../../verification.md#harness-ownership), and [briefing constraints](briefing.md#authoritative-constraints).

### Change Group 2: Deliver staged contact, ownership and content behavior
**Scope**: Implement the existing chair-first path with the amended contracts, then cooler, cups, signs and bounded aftermath. Each accepted content slice is independently reviewable behind coherent feature gating.
**Estimated Effort**: Large, divided into the existing focused implementation tasks and gated slices.
**Tasks**:
1. **Prove the adapter and empty-chair lifecycle.** Complete existing task groups 2 through 4 with Group 1 contracts: the pinned candidate adapter, terrain and static proxies, instance bindings, active render adoption, registry publication during motion, bounded retention and one contact-response owner. Compare updating original buckets against a bounded active pool before selecting the rendering strategy. **Mapping:** Task 2.1 (Engine loading proof) through Task 4.5 (Empty-chair feel gate). **Acceptance:** early device and empty-chair feel gates pass before more recipes, with shared resources, dirty instance matrices, conservative bounds and original chair colors preserved. Sources: [tasks](../../tasks.md), [Profiler rendering comparison](council-profiler.md#required-plan-refinements), [Architect publication finding](council-architect.md#structural-risks-identified).
2. **Complete the occupied-chair production proof.** Add independent seat loads, bracing, clear dismount, forced fall with support-point velocity, recovery and repeat-impact handling through public person capabilities. Integrate one real campsite before wider enrollment, retaining numeric score consequences until the existing policy gate approves a change. **Mapping:** Task 5.1 (Reaction activity boundary) through Task 6.4 (Production acceptance). **Acceptance:** valid claims, one mass/pose publisher, saturated forced release and occupied origin adoption pass in both fixture and production. Sources: [person and campsite tasks](../../tasks.md), [Adversary mandatory release finding](council-adversary.md#vulnerabilities-found).
3. **Add the real cooler, then existing beverages.** Preserve the actual cooler geometry and body ownership; expose holder metadata, partition mechanical lid parts and compare controlled versus physical articulation. Reuse beverage appearance while separating possession, and add exclusive hand/holder/free transfers before posing or contents expansion. **Mapping:** Task 7.1 (Independent cooler descriptor) through Task 8.6 (Cup acceptance). **Acceptance:** holder motion, support loss, full-hand/holder rejection, failed optional transfer, forced release and despawn all preserve one cup representation and bounded capacity. Sources: [design Decisions 7 and 8](../../design.md), [Profiler capacity refinement](council-profiler.md#required-plan-refinements).
4. **Deliver useful signs and bounded aftermath.** Pure route research may proceed after the baseline is stable, but physical sign rollout waits for accepted prop lifecycle/contact behavior. Build a sparse readable family from canonical candidates and validated next-hop evidence; keep fallen/flattened text attached and automatic repair disabled. Add chair righting, same-object cup retrieval and restrained local reactions after transfers and recovery work. **Mapping:** Task 9.1 (Route evidence survey) through Task 10.5 (Aftermath acceptance). **Acceptance:** actual advertised routes work, unknown/rejected targets cannot mislead, and bounded helper claims cannot right occupied furniture or repair excluded signs. Sources: [design Decisions 9 and 10](../../design.md), [Architect sign lifetime finding](council-architect.md#structural-risks-identified).
5. **Expand enrollment and resolve conditional expression with evidence.** Cover camp variants and stage seats, then decide whether articulated falls, saved drinks, spills, loose contents, weight variation and assistance improve the accepted scene. **Mapping:** Task 11.1 (Camp variants and stage chairs) through Task 11.5 (Final capacity and quality gates). **Acceptance:** every candidate is implemented, explicitly rejected with evidence, or preserved as a scoped future feature according to the existing plan; no unmeasured performance concern silently cuts accepted core scope. Sources: [expansion tasks](../../tasks.md#11-expand-coverage-and-resolve-conditional-extensions), [Profiler verdict](council-profiler.md#verdict).

### Change Group 3: Enforce quality gates at each dependent slice
**Scope**: These gates run throughout Group 2, not after all content is implemented. A failed gate blocks its dependent enrollment.
**Estimated Effort**: Substantial recurring verification, with broad runs repeated only for a new workload, failure or relevant change.
**Tasks**:
1. **Exercise clock and generation adversarial cases.** Replay accepted inputs at 30/60/120Hz, same-frame star-plus-chair contact, legacy wall correction, moving cell boundaries, hidden ticking, actual suspension, Passport pause and input/capture locks. Compare original descriptors under changed prop displacement and sign timing, and test runtime canonical-solid overlap reconciliation. **Mapping:** Task 2.2 (Fixed-step clock), Task 2.5 (Cart proxy and resets), Task 3.3 (Registry synchronization), Task 4.2 (Single response owner), Task 11.2 (Cross-system regression matrix), plus Time/Identity/Incidents rows in [verification](../../verification.md#acceptance-matrix). **Pass condition:** finite state, preserved collection semantics and original RNG results, one response owner, no phantom sweep, and documented invariant tolerances rather than assumed cross-browser bit identity. Sources: [Adversary vulnerabilities](council-adversary.md#vulnerabilities-found), [Architect frame finding](council-architect.md#structural-risks-identified).
2. **Stress all ownership lifetimes together.** Fill protected capacity, then release both loveseat sitters and held/holder cups together; also despawn a holder. Unload the origin of an occupied loveseat, test failed destination preparation and music interruption, acquire a replacement claim, then deliver the stale release. Travel across many origins with forced eviction/revisit; test both removal orders and reset. For signs, compare destination-first/sign-first loading, destination unload/reload and actual placement rejection. **Mapping:** Task 3.7 (Lifecycle stress gate), Task 5.6 (Loveseat and seat validity), Task 6.2 (Streaming and people integration), Task 8.6 (Cup acceptance), Task 9.6 (Sign integration gate). **Pass condition:** one identity/representation, valid claims and support, no cap overrun or monotonic metadata growth, harmless stale releases and residency-independent sign truth. Sources: [Architect structural risks](council-architect.md#structural-risks-identified), [Adversary saturation/adoption findings](council-adversary.md#vulnerabilities-found), [Profiler reserve refinement](council-profiler.md#required-plan-refinements).
3. **Measure a controlled workload envelope on real devices.** Include sparse motion, dense piles, chain reactions, rapid activation and a sleeping neighborhood. Record body/collider recipes, joints, contacting pairs, continuous-collision checks, substeps, mandatory/cosmetic queue work, cold construction, warm p50/p95/p99, upload cost and memory. Compare one moving chair, mixed chair styles and adopted props from several camps using bucket counts, changed matrices, uploaded bytes where inspectable, transform/bounds time and actual submitted triangles. Match quality rung, DPR, render targets, viewport, population, time of day and feature state for attribution, then run normal adaptive quality separately. Include sign planning/label spikes and cache bounds. **Mapping:** Task 2.6 (Early device gate), Task 3.2 (Chair instance bindings), Task 3.4 (Moving render adoption), Task 6.4 (Production acceptance), Task 7.6 (Cooler acceptance), Task 8.6 (Cup acceptance), Task 9.6 (Sign integration gate), Task 11.5 (Final capacity and quality gates). **Pass condition:** measured provisional and final per-tier limits cover both allocation and sustained work; no fabricated milliseconds or device headroom. HUD guides of Low 80 draws/150k triangles, Mid 200/400k and High 400/1.2M remain context, with baseline/delta disclosed if already exceeded. Source: [Profiler refinements and estimates](council-profiler.md#required-plan-refinements).
4. **Verify actual runtime paths and resource teardown.** For each accepted implementation slice, run `npm run check`, `npm run build`, affected entity/interaction/hub surfaces and a ready-title click into the real game, inspecting console and streaming. Inspect Noon/Midnight and relevant Low/Mid/High paths, including `?perf=low` and `?perf=mid`, with `mute=1` except explicit bounded audio checks. Verify iOS synchronous start-gesture unlock independently of scripted start. Test initialization failure and coherent disabled behavior, shim/material safety, deliberate shadow policy, lake ownership and shared disposal. **Mapping:** Task 6.4 (Production acceptance), content acceptance tasks, Task 12.1 (Release verification record). **Pass condition:** no sandbox-only acceptance, production base-path loading works, and task-owned browser/server resources are gone. Sources: [verification ladder and ownership](../../verification.md), [current project policy](../../../../../AGENTS.md#run-and-verify).

## Final Recommendation
Proceed with mitigations: incorporate the contracts, task mappings and negative scenarios above before runtime work, then follow the occupied-chair production proof through the existing staged content sequence. The concurrently updated design now adopts the proposed late contact barrier, reaction-owned seat transfer and the other core contracts; these choices are supported planning resolutions, but their runtime behavior remains subject to the specified gates. No second engine candidate, scheduler rewrite, global routing framework or measured capacity claim is justified by this review.
