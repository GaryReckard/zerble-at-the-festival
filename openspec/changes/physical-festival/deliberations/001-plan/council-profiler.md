## Profiler's Position

TL/DR: Proceed with the bounded simulation approach, but make frame-work admission, saturation behavior and controlled device comparisons explicit before accepting the engine proof. The plan already contains the right allocation, solver and render measurements; its remaining performance risk is treating bounded storage as a bounded frame cost.

### Priority Sequence

1. Strengthen Group 2 (engine proof) with work admission and dense-contact tests before accepting provisional capacities. Task 2.4 (Admission and residency) limits storage, while Task 2.6 (Early device gate) measures activation spikes; neither explicitly budgets terrain/static-proxy construction alongside the existing shared streaming deadline (`tasks.md:20-22`; `src/world.js:115-137`).
2. Prove the chair's existing instance bindings before choosing an active rendering pool. Current batching groups by geometry/material identity, writes matrices, then removes the original child meshes (`src/models/campsite.js:1054-1076`). Preserve that static economy and compare active pool cost against updating existing buckets, as Design decision 4 already allows.
3. Establish a saturated occupied-chair encounter before broadening into cups and contents. The plan protects active/support-critical objects, but the cup requirement also preserves the source on allocation failure; a physically unavoidable release must have a valid bounded representation even when optional admissions have consumed capacity (`design.md`, decisions 2, 6 and 8; `specs/drink-props/spec.md`, “Free-body capacity is unavailable”).
4. Retain the one-campsite device gate, then repeat measurements only for changed workload classes: cooler articulation, transferable cups, signs and conditional ragdolls (`tasks.md:57,66,75,84,98-100`). These are distinct cost changes, so the early chair proof cannot certify them.

### Required Plan Refinements

**Add a work-budget contract to Task 2.4 (Admission and residency).** Record maximum body/collider creations per frame, terrain/static-proxy construction time and queued admissions, alongside resident counts. Share or explicitly allocate within the world-owned streaming allowance rather than silently adding a second full allowance. Use predicted motion to prepare support ahead of contact, with a tested policy when required support is not ready. This is necessary because a deadline that only decides whether construction starts cannot stop a single synchronous build from overrunning it; the existing performance audit documents that distinction (`.claude/rules/performance.md`, “2026-10-08 audit,” priority 5; `src/world.js:115-137`). No new fixed millisecond value is justified by this documentation review.

**Expand Task 2.6 (Early device gate) into a workload envelope.** Record bodies, colliders per recipe, sleeping residents, joints, simultaneous contacting pairs, enabled continuous-collision checks, substeps and application contact-event processing separately. Include sparse motion, a dense pile, a chain reaction, rapid activation and a fully sleeping neighborhood. Add a bounded event queue with separate policies for mandatory gameplay transitions and discardable cosmetic feedback; never silently drop required support/claim or penalty events to hit a timing target. The plan already separates sound, score and incidents, making this a refinement of the existing boundary rather than a new subsystem (`design.md`, decisions 2 and 10; `verification.md:36`). Record whether the solver finishes within its measured budget; bounded substeps alone are not proof of that.

**Reserve capacity for mandatory transitions.** At admission, account for the maximum releasable person/cup bodies and render slots associated with each supported assembly, or specify an equally concrete bounded fallback with equivalent visible ownership. Reject optional contents before consuming that reserve. Add a saturated fixture where a loveseat's occupants and held/holder cups release together, then assert one representation per object and finite resident counts. This closes the gap between protecting existing supports and preserving valid transfers (`tasks.md:45-49,71-74`; `specs/drink-props/spec.md`, “Exclusive hand and holder transfer”).

**Make rendering measurements comparative.** Extend Task 3.2 (Chair instance bindings) and Task 3.4 (Moving render adoption) with one moving chair, several moving styles in one camp, and adopted props from multiple origin camps. Record bucket counts, changed matrices, uploaded bytes where inspectable, CPU transform/bounds time, draw/triangle deltas and memory high-water marks. Compare full-buffer updates, supported partial updates and the bounded active pool only where measurement warrants it. Do not merge unrelated geometry or reduce existing chair color variety merely to force a numerical draw target (`src/models/campsite.js:1054-1076`; `.claude/rules/performance.md:48-51`). Preserve no new shadow casters as the default (`verification.md:40`).

**Tighten comparison conditions and sign limits.** Add quality rung, actual DPR/render-target dimensions, viewport, population, time of day and feature state to each baseline/feature capture. Use a matched-quality comparison for attribution and a separate normal adaptive-quality run for the player experience. Give the sign graph a node/edge/query bound, label caches a count/byte bound and explicit epoch invalidation, and record planning/label-generation spikes during travel (`verification.md:36-40`; `ARCHITECTURE.md:591-605`; `design.md`, decision 9). Do not require a new worker or new post-process pass before measurements demonstrate a need.

### Budget Estimate

- **Draw delta**: Updating already visible chair instance transforms can add **0 draws** while retaining the original buckets. An active pool adds **B occupied geometry/material buckets**, less any emptied original draws; a mesh-per-part fallback adds up to **N × P draws** for N active props with P separately rendered parts. These are analytical bounds, not measured results, based on `src/models/campsite.js:1054-1076`. The current closed cooler has three batches, so physical motion alone need not add draws; articulation and labels require new measured deltas (`bin/test-camp-cooler:24`; `tasks.md:64-66,82`).
- **Triangle delta**: Reusing existing prop geometry adds **0 logical visible triangles** for motion alone. Migration must count actual submitted triangles because hidden instance slots may remain in submitted batches. New ambient cups/signs and any split lid introduce recipe-dependent costs that cannot be quantified before recipes exist. The current cooler test caps its geometry at **1,500 triangles**, which is a preservation check rather than a physics budget (`bin/test-camp-cooler:46-53`).
- **Tier context**: HUD guides remain Low **80 draws / 150k triangles**, Mid **200 / 400k**, High **400 / 1.2M**, with Low the smallest allowance. There is no measured baseline here from which to calculate remaining headroom. The current rules explicitly caution that HUD thresholds need recalibration, so compare the measured baseline and feature delta instead of claiming global compliance (`.claude/rules/performance.md`, “2026-10-08 audit” and “Don't try to optimize before you've measured”; `verification.md:38`).
- **Cost type**: Both allocation stalls and steady-state FPS, with additional bounded memory residency. Sleeping storage, terrain, support groups and event work require separate accounting (`design.md`, decision 2; `verification.md:36`).
- **Low/mid-tier verdict**: **At risk until the early device gate; the proposed instancing/pooling approach is appropriate.** Use current tier settings as the baseline. In particular, current Low DPR cap is **1.25**, not the historical 1.0 (`src/perf.js:100`; `ARCHITECTURE.md:577`). Do not alter unrelated render settings to make the physics result appear cheaper.

### Evidence Scope

This is a source-and-plan review, with no dependency installed and no runtime/device measurements. The requested legacy `.Codex/` performance paths are absent; their present `.claude/` counterparts were read, including both historical pass plans. Current `AGENTS.md` overrides stale importmap wording in the protocol/config, and current source overrides historical numeric tier defaults. All recommendations above are implementation acceptance refinements, not claims that an unimplemented feature already regresses.

### Verdict

- **Verdict**: Proceed with mitigations.
- **Key Concern**: Storage caps alone do not bound activation, dense-contact or render-upload work within a frame.
- **Recommendation**: Integrate the five refinements into the existing early engine, lifecycle and measurement tasks, retain the one-campsite production gate, and select numeric limits from the specified device workloads before broader enrollment. No performance-driven scope cut or alternative engine choice is justified yet.
