## Architect's Position

TL/DR: Proceed with mitigations. A pure passport store, a separate DOM view and main.js integration match the existing architecture, provided collection eligibility and restart restoration have explicit contracts before hooks are added.

Inject storage and clock as proposed. This follows the existing pure `runState.js` and `scoring.js` separation rather than creating another gameplay controller (`ARCHITECTURE.md:431`, `ARCHITECTURE.md:435`; `design.md:6`). Specify concrete stamp IDs/criteria and snapshot fields before building presentation, since the requirement promises readable earned and unearned criteria (`specs/festival-passport/spec.md:20`).
2. **Have main.js own eligibility and lifecycle.** Derive one predicate for active collection from running, intro lock, visibility, passport state and game-over state, and apply it to every event path and active-time accumulator. Capture the generated entrance before saved-location overrides; restore visit state through the existing settings snapshot rather than inventing another resume channel (`src/main.js:466`, `src/main.js:727`; `design.md:6`).

### Structural Risks Identified

- **Independent simulation and collection lifetimes:** Hidden tabs explicitly keep ticking, and `running` alone does not exclude intro or game-over gameplay paths (`src/main.js:966`, `src/main.js:973`, `src/main.js:1578`). A passport collection gate must cover callbacks as well as movement, while input suppression must cover honk, camera, upgrades and trip edges, not just neutral steering (`src/main.js:1017`, `src/main.js:1023`, `src/main.js:1033`). Keep this orchestration in main.js; the store receives accepted events and the DOM module exposes open state. Do not create a second simulation loop.
- **Entrance and restart ownership:** Saved launch coordinates overwrite the generated spawn, and run/scoring restoration is intentionally conditional on the selected mode (`src/main.js:466`, `src/main.js:624`). Capture the entrance before that overwrite and document whether passport visit continuity is independent of mode changes. Restore absolute visit values without adding already-persisted visit totals into all-time totals again; test restart followed by another restart and ordinary reload (`src/main.js:727`; `specs/festival-passport/spec.md:5`).
- **Relocation and exploration records need separate tests:** Bracketing physics excludes the actual rescue/debug jump from driven distance, but absolute radius sampled on a later stationary or moving frame can still promote a relocated position into the farthest record. Specify the intended post-relocation eligibility and verify it explicitly, since rescue and debug teleport directly mutate position (`src/main.js:1703`, `src/main.js:2255`; `specs/festival-passport/spec.md:18`). Preserve planar x/z measurements without editing terrain or cart physics (`design.md:6`, `design.md:12`).
- **Stage identity must outlive streamed objects:** ChallengeTracker currently deduplicates rounded coordinates in a per-instance set, while registry IDs are allocated on registration (`src/bubbleChallenges.js:11`, `src/bubbleChallenges.js:25`, `src/bubbleChallenges.js:138`; `src/registry.js:7`, `src/registry.js:56`). Send primitive coordinates to the passport and deduplicate by seed plus quantized coordinates there. Do not register passport content, retain stage objects, or alter chunk ownership. Allow repeated proximity notifications to reach passport deduplication so a first notification rejected while collection is paused cannot permanently hide that stage.
- **Migration must preserve two existing owners:** BubbleProgress still owns lifetime smiles used for unlocks, and scoring owns multiplied spendable score (`src/bubbleChallenges.js:70`; `src/bubbleProgress.js:94`; `src/main.js:1149`). Import the legacy total once, retain unlock behavior, and feed future raw pickups to both owners from the existing collection branch. Persist the migration marker with the imported total, and never project imported history as new analytics increments (`design.md:14`).
- **Local persistence and analytics must remain independent:** Analytics already swallows absent/throwing tags, and current session-end reports are cumulative snapshots (`src/analytics.js:36`; `src/main.js:911`). Passport interval/hide reports need their own consumed-increment checkpoint; duplicate visibility/pagehide calls must not resend increments. Define this as once-per-checkpoint emission attempts, because the existing fire-and-forget transport provides no server acknowledgement. Persist stamps independently of send success and explicitly test unavailable tags (`tasks.md:5`; `specs/festival-passport/spec.md:24`).
- **Current importmap rules supersede historical council wording:** The charter describes three full pages, but current project instructions and the no-build rule require all five, including terrain and map sandboxes (`openspec/council/charter.md:49`; `AGENTS.md:96`; `.claude/rules/no-build.md:18`). Follow the five-page proposal and preserve concurrent edits. The feature needs no new world entries, material changes, model builders or disposal ownership (`proposal.md:19`; `src/registry.js:46`).

### Verdict

- **Verdict**: Proceed with mitigations
- **Key Concern**: A consistent collection and visit-lifecycle boundary across background simulation, modal state, relocation and settings resume.
- **Recommendation**: Retain the proposed two-module split, make main.js the integration owner, and resolve the cited lifecycle contracts in foundation tests before connecting callbacks. The plan does not require world, physics, RNG, rendering or audio ownership changes.
