## Synthesized Plan

### Change Group 1: Contracts and inspection foundation
**Scope**: Close the acceptance gaps and establish a cheap verification surface before live hooks.
**Estimated Effort**: Medium; roughly one focused implementation session, including behavioral tests.
**Tasks**:
1. Amend `design.md`, the festival-passport delta spec and `tasks.md` with a state matrix covering title, intro, active play, hidden tab, passport, game over and settings restart. `main.js` owns one collection predicate used for time and every event callback. A passport opened during play pauses gameplay progression, movement, damage, resource consumption and run/day clocks while rendering and DOM interaction continue; closing restores the prior state without elapsed-time catch-up. Hidden-tab behavior outside the passport remains governed by the existing game, but passport collection is ineligible there. Include capture state in collection ineligibility as recorded in the accepted design. Keep this orchestration in the existing loop (`council-architect.md:13`; `council-anthropologist.md:6,12`).
2. Define relocation semantics separately from physics-distance sampling. Use the accepted contract in `design.md`, “Resolved lifecycle contracts”: compare the prior endpoint with the next physics start, and explicitly mark rescue. Any external relocation disables exploration records, stage discovery and exploration stamps for the remainder of the visit; only a new visit resets eligibility, while settings resume preserves the restriction. Keep current physical distance as a visit gauge and continue measuring subsequent genuine driven distance, with visible wording that exploration records are paused. Test that tiny movement or a later return after a jump cannot silently restore record eligibility (`council-adversary.md:11`; `council-architect.md:16`).
3. Define the save/resume contract: capture the generated entrance before the saved-position override; ordinary reload or a new game begins a new visit; explicit Apply & restart preserves the passport visit, entrance, deduplication and telemetry state even if the selected mode changes. Preserve the existing mode-match guard for run/scoring restoration, and never revive a dead run through passport restoration. Restore absolute visit values without adding them again to all-time totals (`council-adversary.md:17`; `council-architect.md:15`).
4. Specify schema validation, one-time legacy-smile migration, and the initial public stamp catalog before tests. Use the six accepted definitions in `design.md`, “Resolved lifecycle contracts”: Wanderer requires 500 metres from the entrance this visit; There and Back requires reaching 500 metres and returning within 25 metres in the same eligible visit; Stage Hopper requires three distinct stages this visit; Night Owl requires a stage visit at nightness greater than 0.5; Smile Spreader requires 1,000 lifetime raw pickups; Bubble Maker requires 1,000 successful lifetime emissions. Assign stable IDs and persist earned stamps permanently. Imported smiles trigger neither stamps nor analytics during migration; a subsequent accepted pickup can earn Smile Spreader. Relocation disables the four exploration stamps for the remainder of the visit. Keep damaging bonks as a statistic without an achievement reward. Validate finite nonnegative counters, record relationships, stage keys, known stamp IDs and resume data; persist migration marker and imported total together and latch the marker in memory if saving fails (`council-anthropologist.md:7,14-15`; `council-adversary.md:23`).
5. Establish injected storage/clock tests and deterministic empty, progressed, migrated, long-total and save-failed snapshots. Provide a documented local DOM preview that instantiates the production menu with those snapshots, plus a local `__dbg` inspection/opening drill. Keep preview progress out of real saves and analytics. Define checkpoint consumption as local emission attempts, not delivery acknowledgement, before transport implementation (`council-anthropologist.md:5,24`; `council-architect.md:5,19`).

**Exit condition**: The accepted contracts are reflected consistently in the change artifacts, fixtures are reviewable, and pure behavioral cases cover the lifecycle decisions. This group can ship as documentation and development scaffolding without exposing the feature.

### Change Group 2: Store, modal and authoritative integration
**Scope**: Implement the record and view, then connect narrow observations to existing owners.
**Estimated Effort**: Large; roughly two focused implementation sessions.
**Tasks**:
1. Implement `src/playerStats.js` as a DOM-, Three.js-, registry- and GA-free store with primitive event inputs, immutable snapshots, validated serialization, migration, stamps and separate consumed telemetry checkpoints. Retain BubbleProgress as the bubble-unlock owner and scoring as the multiplied-score owner; feed accepted raw smile pickups directly, rather than differencing independently growing totals (`council-architect.md:5,18`; `ARCHITECTURE.md:430-438`).
2. Implement `src/passportMenu.js` and CSS against the fixtures before live hooks. Provide This visit / All time views, earned and unearned criteria, accessible tabs/dialog labeling, Escape close, focus containment/restoration, narrow and landscape-touch layouts, and storage scope/failure wording. Coordinate overlapping menus in main.js. Block all gameplay consumers, clear or consume pending action edges and touch latches, and require fresh input after closing; a focus trap alone is insufficient (`council-adversary.md:15`; `council-anthropologist.md:16,18`).
3. Wire the single eligibility predicate into active time, raw smiles, damaging bonks and boardings, and bracket only the actual cart update for x/z driven distance. Integrate the agreed relocation boundary at debug teleport/rescue call sites without editing cart physics, world generation or terrain. Keep collection rejection explicit in asynchronous or independently invoked observers (`council-architect.md:7,9,13,16`; `council-adversary.md:13`).
4. Observe successful bubble initialization for ordinary, special and unlock-burst paths. Full pools and invalid special IDs produce zero births, and instrumentation adds no RNG draws or changes to existing draw order. Send primitive stage coordinates on repeated in-radius evaluations and deduplicate seed-qualified quantized keys in the passport, independently of ChallengeTracker's unlock history, so an earlier ineligible encounter cannot consume discovery (`council-adversary.md:13,21`; `council-architect.md:17`).
5. Add whitelist-only GA transport for 60 active-second progress batches, hide flushes and newly earned stamps, with additive increments distinct from current/max gauges. Use one synchronous consume-checkpoint operation before calling the failure-swallowing transport. For Apply & restart, flush/consume first, then serialize the updated resume checkpoint, then reload; a later hide/pagehide sees no additional delta. Baseline migrated history, avoid historical replay after an ordinary boot, and consume absent/throwing-tag attempts without backfilling when GA returns. Persist local progress independently; storage failure limits continuity and must not block play (`council-adversary.md:19`; `council-architect.md:19`; `ARCHITECTURE.md:600-612`).
6. Wire title and in-game controls, restore passport state through the existing settings channel, and add both new modules to all five importmaps: `index.html`, `sandbox.html`, `hub-sandbox.html`, `terrain-sandbox.html` and `map-sandbox.html`. Preserve the synchronous trusted-gesture `Sound.init()` chain, Three shim, RNG streams, registry ownership, shared disposal, nightness contract and existing shadow policy. This DOM feature requires no model, world registration or geometry; its DOM preview replaces an irrelevant entity-model entry, while real-game boot remains mandatory (`council-architect.md:11,20`; `.claude/rules/no-build.md:17-40`; `AGENTS.md:94-127`).

**Exit condition**: The feature is usable through the real title/game controls and has no dependency on GA availability. Land this group together with its quality gates, because partially connected lifecycle hooks are not independently safe to expose.

## Final Recommendation
Proceed with mitigations, using the four groups in order and treating the foundation contracts as prerequisites for live hooks. Adopt a true gameplay pause while reading, repeated stage observations with independent deduplication, and restart-ordered telemetry checkpoints; apply the accepted visit-long relocation restriction and six-stamp catalog already recorded in `design.md`. Continue in the feature worktree on `codex/festival-passport`, with no user escalation required for these routine implementation decisions.
