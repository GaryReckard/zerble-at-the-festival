## Adversary's Position

### Priority Sequence

1. Define the eligibility and relocation contracts in the pure store and behavioral tests before adding hooks. A running game continues simulating while hidden, and stage discovery has a separate deduplication history, so a timer-only pause cannot establish honest stats (`src/main.js:963`, `src/main.js:1578`, `src/bubbleChallenges.js:25`, `src/bubbleChallenges.js:133`).
2. Define settings-resume ownership, migration baselines and telemetry checkpoints together. Settings serializes before reload, whereas the existing hide handler subsequently reports analytics; a snapshot of counters alone does not define which increments were already attempted (`src/settings.js:245`, `src/main.js:918`, `src/analytics.js:33`).
3. Integrate the modal and successful-emission callbacks, then exercise the real game on Low and Mid with blocked storage and absent/throwing GA. Preserve the synchronous audio gesture and all five importmaps (`src/main.js:793`, `src/main.js:827`, `.claude/rules/no-build.md:17`, `AGENTS.md:61`).

### Vulnerabilities Found

- **A local physics delta does not prevent a teleported exploration record**: Measuring immediately around `zerble.update` excludes the jump from driven distance, but the next valid movement still begins at the remote location and can award its absolute distance from the entrance. Both debug teleport and the legitimate rescue directly replace x/z (`src/main.js:2255`, `src/main.js:1703`), while the proposed design promises relocation cannot inflate exploration records (`openspec/changes/festival-passport/specs/festival-passport/spec.md:13`). Define explicit relocation handling for current/farthest distance and stage discovery, rather than relying on a speed cutoff. Test teleport, a small subsequent movement, a later return, and rescue. Severity: **High**.

- **Gating time alone still counts hidden simulation and can permanently lose a stage discovery**: Bubbles, stage evaluation, crowd boardings and smile collection continue inside the running loop, including the hidden-tab timer path (`src/main.js:1074`, `src/main.js:1143`, `src/main.js:1578`). Each passport mutation must check the common eligibility policy, including event callbacks, rather than taking later differences from lifetime-smile or raw-score totals. If the new stage callback fires only when `ChallengeTracker.stagesSeen` first changes, entering a stage while hidden/intro/modal marks it seen while passport rejects it, so returning visibly never earns it. Invoke the eligible passport observer on each in-radius evaluation and let the passport deduplicate its own seed-qualified identities, while retaining the existing unlock history (`src/bubbleChallenges.js:133`). Test hidden entry followed by visible entry, unload/reload, and restored-visit re-entry. Severity: **High**.

- **Copying the upgrades overlay does not suppress held controls or touch input**: The existing overlay stops keydown propagation and traps focus, but Input retains held keyboard state and reads touch axes directly; only blur/editable focus clear keyboard state (`src/upgradesMenu.js:114`, `src/input.js:45`, `src/input.js:83`). The loop separately reads honk, camera, music, trip acceptance and blast controls (`src/main.js:987`, `src/main.js:1018`, `src/main.js:1033`, `src/main.js:1068`). Gate all gameplay consumers while passport is open, handle pending edges and touch latches deliberately, and use the complete neutral input contract rather than `{}` (`src/main.js:691`, `src/main.js:973`). Verify opening while W/boost or the joystick is held, keyboard/touch close, and no delayed action after closing. Severity: **High**.

- **Visit preservation can undo an existing mode-boundary correction**: The snapshot is consumed once at boot, but score/run restore is deliberately deferred until Start and requires a matching mode (`src/main.js:101`, `src/main.js:617`). Gary's correction in commit `14e9512c`, confirmed with blame on those lines, protects against a Festival snapshot leaking into Cruisin'. Preserve that guard and define separately whether the passport visit spans a changed mode, a dead run, and the resumed title card. Capture the original entrance after generated spawn placement but before the launch-position override, otherwise settings reload makes the saved location the new entrance (`src/main.js:378`, `src/main.js:466`). Test same-mode restart, changed-mode restart, ordinary reload, and restart after game over (`src/main.js:731`). Severity: **High**.

- **An in-memory telemetry checkpoint does not survive settings restart ordering**: Settings writes its resume object before `location.reload`, while hide/pagehide can still flush a final progress batch (`src/settings.js:245`, `src/main.js:918`). Restoring counters with a zero or stale checkpoint resends prior increments. Specify an ordered flush/checkpoint/snapshot operation, make repeated hide/pagehide idempotent, and baseline migrated smiles so they never become new telemetry. Existing `send` returns no delivery acknowledgement and swallows missing/throwing tags, so promise at-most-once local attempts rather than confirmed delivery; never backfill historical totals when GA becomes available (`src/analytics.js:33`, `openspec/changes/festival-passport/design.md:14`). Severity: **High**.

- **Bubble attempts differ from successful births**: `_spawnOne` returns early when the ordinary pool is full and currently returns no success value; `_spawnSpecialOne` explicitly rejects invalid types and a full pool (`src/bubbles.js:465`, `src/bubbles.js:516`). Counting accumulator iterations overstates actual emissions, particularly under blast or pool pressure (`src/bubbles.js:271`, `src/bubbles.js:290`). Count only after successful initialization, covering regular specials and unlock bursts without inserting RNG calls. Test both full pools and invalid special IDs. Severity: **Medium**.

- **Save parsing and migration need a bounded, idempotent contract**: The existing lifetime-smile owner normalizes parsed values and exposes an independently saved counter (`src/bubbleProgress.js:9`, `src/bubbleProgress.js:123`). A schema version alone does not establish numeric validity or an import baseline. Validate finite nonnegative counters, seed-qualified stage keys, stamps and resume payloads before adoption; persist the imported total and migration marker in the same passport record, and keep that marker latched in memory after a failed write. Test corrupt JSON, valid JSON with malformed fields, throwing reads/writes, and retry after failure. Do not use `max(oldLifetime, passportLifetime)` on every reload as a substitute for migration, because hidden simulation can continue growing the legacy counter (`src/main.js:1149`). Severity: **Medium**.

### Verdict

- **Verdict**: Proceed with mitigations
- **Key Concern**: The plan must specify eligibility and relocation behavior for every mutation, because physics-only measurement cannot enforce the promised exploration semantics.
- **Recommendation**: Resolve these contracts in store tests and focused integration cases before implementation. The proposed pure store and DOM view fit the engine without world ownership, RNG, material or geometry changes (`openspec/changes/festival-passport/design.md:6`, `openspec/changes/festival-passport/design.md:11`). Preserve the audio unlock chain (`src/sound.js:285`, `src/sound.js:307`, `src/sound.js:321`) and require a trusted title-card start in the real-game smoke test; scripted debug start explicitly bypasses that dependency (`src/main.js:1981`). This is a source-backed planning review, not runtime verification.
