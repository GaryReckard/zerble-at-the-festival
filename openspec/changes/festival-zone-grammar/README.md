## TL;DR

Two playtests called the procedural festival "a jumbled mess" — trucks clipping
vendor booths, porta-potties scattered, a drum circle inside a food-truck ring,
the entrance arch sitting beside the dancefloor instead of out on the road. It's
**one root cause**: the planner places clusters as *dots with a clear-radius*,
but the builders construct *bigger oriented shapes* than those radii, so things
that look spaced-out on paper actually overlap. This change replaces the
"scatter and nudge apart" planner with a **zone grammar** — each hub slots
non-overlapping, oriented zones in a sensible order around its front-facing axis
— and rewires the builders so the plan and the build finally agree. Success is
**numeric** (every error-severity linter rule → 0 across 10 seeds; baseline was
106 errors / 92 warns) and **Gary-judged** (in-game 3D screenshots).

## The Problem

A festival "hub" is generated by two cooperating layers. The **planner**
(`festival.js`) decides "a food court goes about here" using a single number for
how much space each thing needs. The **builders** (`chunks.js`) then construct
the actual trucks, tents, and stages — which are bigger, oriented shapes that
exceed that number. Nothing checks the two against each other, so the planner
settles clusters at distances that *guarantee* clipping. Three things compound
it: the cleared dance area in front of a stage only pushes *trees* away (other
clusters ignore it), the builders place each truck/booth without checking what's
already there, and there's no rule keeping stages on neighbouring hubs apart.
The result is the jumble players see. The previous change (`worldgen-layout-harness`)
made all of this *measurable* and *visible* without changing placement; this
change changes placement.

## Proposed Fix

- **Builders speak data first.** Each builder splits into a pure "where does
  everything go" half (positions, sizes, angles — no 3D) and a "build the meshes"
  half. This lets the planner and the linter reason about *true* extents and runs
  headlessly. (Behaviour-preserving; lands one builder at a time, each gated so
  the world doesn't change yet.)
- **The crowd stops depending on graphics settings.** Today the number of
  festival-goers (and the random draws they consume) varies by quality tier, so
  the *same seed* builds a slightly different layout on a phone vs a desktop. The
  crowd's parameters get pre-decided in the data half, making layout
  tier-independent — while the *visible* crowd size still scales with the tier.
- **Zones, not scatter.** Per hub, place non-overlapping oriented zones in
  priority order: stage + a hard-reserved clear front area → vendor aisles that
  straddle a road with full campsites behind them → food courts set back from
  stages, off the road, sometimes with a little spur road to the middle → the big
  drum circle in a forest clearing with a drivable path in → porta-potties
  attached to a neighbour, facing it → the arch out on the road as a threshold
  you drive through → bubble vendors, now sprinkled sparingly. A zone that can't
  fit cleanly is dropped, not crammed in.
- **One deliberate world change.** Reworking placement regenerates the procedural
  world, so the determinism "fingerprint" moves — **once**, on purpose,
  re-recorded and re-verified. The experimental world is still behind a flag
  that's OFF in the shipped game; flipping it on is a separate, later step.

The technical "how" is in [design.md](design.md); the full risk review is in
[deliberations/001-initial/results.md](deliberations/001-initial/results.md).

## Key Decisions

- **Crowd pre-roll lands FIRST, before the builder extraction** (deliberation
  reorder). The crowd draws a variable, tier-dependent number of random values
  from each cluster's stream; until that's hoisted out, the "did the world stay
  identical?" gate isn't trustworthy.
- **Extract builders behaviour-preserving first, then change placement.** The
  determinism fingerprint moves exactly once — at the placement commit — so any
  accidental change localizes to that one commit.
- **Spur roads and the drum's access path are cosmetic "path" records, not real
  roads.** Making them real roads would move a *second*, frozen fingerprint and
  slow generation; as decoration they're a clean one-way data flow.
- **A "Slice 0" spike runs first** to confirm how many builders actually need the
  full split before grinding through the riskiest refactor (the entrance-arch fix,
  for instance, is planner-only and needs no extraction).

## Risks & Watch-outs

- **This regenerates the experimental world** — by design, behind an OFF flag, no
  saved game depends on it, the fingerprint move is logged and re-verified.
- **Sandbox-pass ≠ game-pass.** The data→mesh split is exactly the shape of a past
  boot-crash bug, so the real game is booted at both flags and all three quality
  tiers after every builder commit, not just at the end.
- **A "drivable path" is invisible to the linter** (paths are excluded from the
  overlap check), so the corridor is reserved explicitly in the planner — or a
  tent lands in it.
- **A stale model-dimension copy could ship a clip the linter can't see** — the
  drift guard gets promoted from a quiet warning to a hard test failure before
  the extents become load-bearing.
- **Not doing:** flipping the experimental world on (separate later change);
  per-truck cosmetic customization (future).
