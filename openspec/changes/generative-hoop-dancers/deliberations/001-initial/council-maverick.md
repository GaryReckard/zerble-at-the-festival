## Maverick's Position

### Priority Sequence

1. **Make the first proof a complete little performance.** Build the production-path workshop and a minimal optional flow-pose adapter together, then show one orbit that becomes an isolation, transfers hands and returns as a recognizable answer. Keep the classic preview beside it. The design correctly names this phrase but currently separates the workshop from the adapter it needs (design.md:39,55-57; tasks.md, groups 2 and 4). Permit the minimum adapter during the workshop stage instead of producing an inspection UI around a substitute dancer.
2. **Prove contact in the existing rig, then author a few excellent movement sentences.** The current right-hand CPU function mirrors the arm shader, while the shader already supports two independently articulated arms (src/personMotion.js:58-62,100-114). Extend the reference to both hands and build valid paths within that workspace. Authoring a few contact-valid paths is more valuable initially than building a broadly capable inverse-kinematics search.
3. **Compile a bounded whole-session score before performing it.** The existing activity sessions last 18 through 25 seconds and retain a performance elapsed clock (src/people/hulaActivity.js:33; src/people/hulaSession.js:9,44-47). Generate an entrance, motif, development, flourish and resolution at session entry using the independent seed, then sample the resulting compact score. Validate its whole swept envelope before starting. This produces continuous variation across encounters without requiring runtime stochastic planning at every phrase boundary.
4. **Judge the result from the player's actual viewing distance before expanding the library.** Require a recognizable silhouette change, a held isolation and an obvious phrase return in the normal game camera as well as close inspection. The charter explicitly prioritizes perceptible impact at driving speed and camera distance (openspec/council/charter.md, Project-Specific Resolution Rules, rule 3). Contact precision remains necessary, but a technically diverse score that reads as the same spinning ring has not earned the feature's creative promise.
5. **Expand through the promised vocabulary using the same score contract.** Add supported rolls and flight/catch, then validated two-hoop counterpoint and the bounded partner exchange. Retain these stages in the plan. Use the existing pair-session acquisition/interruption structure as the ownership reference before inventing another generic pair framework (src/people/frisbeeSession.js:9-35,52-62). Verify each stage through production claims and the full game.

### Impact and Simplification

**The strongest part is already present:** motifs, answers and returns make the choreography legible, while an isolated score sampler lets it remain reproducible (design.md:15-25). Keep that as the center of the feature. The primitive vocabulary is an implementation tool; the player should experience a performer with taste and a rhythm of effort and rest.

**Reuse the current presentation.** There are already eight colored hoop styles, a compact torus and a shared vertex-colored emissive material (src/models/hulaHooper.js:26-58). The live activity already polls nightness and raises their emission (src/people/hulaActivity.js:58). Choreography can therefore become striking at night without adding trails, lights or a new material system. Preserve those resources as the baseline and let movement supply the novelty.

**Keep clearance conservative and local.** The existing placement checks only a .45 building radius and 2.2 separation between selected performers (src/people/hulaActivity.js:31,66). A flow phrase needs a larger swept envelope, but this does not require a new physics engine. Store each validated phrase's conservative envelope, reserve it before entry, and use a safe exit if the scene stops supporting it. Do not silently scale an already validated hoop path until its hand contacts break.

**Name the aesthetic acceptance tests explicitly.** Alongside contact and lifecycle tests, compare a fixed set of seeds for three visible qualities: whether the motif can be recognized on its return, whether the profiles differ in silhouette and pacing, and whether the score contains stillness as well as flourish. The design already acknowledges that distinct seeds do not prove interesting choreography (design.md:62); make the workshop's score inspection and normal-camera captures support those three judgments rather than using transition counts as a substitute.

### Alternative Approach

**Compile a “movement sentence” from a few complete, validated phrase families, then mutate its interpretation.** Instead of allowing all primitives to participate in an online search, begin with a small set of families whose contact topology is known: circle → isolation → handoff → answer, or body orbit → lift → overhead release → catch. Their legal parameters expose selected hand, plane range, tempo contour, pause placement and body counter-motion. The independent seed selects a family and compatible parameter variants, while the score samples analytical motion throughout the performance. The compiler can still use the proposed primitive vocabulary internally; the outer structure guarantees that the resulting performance says something coherent.

- **Value:** A whole score has a deliberate beginning and ending, direct seek becomes cheap, and the compiler can validate all reach/contact/clearance requirements before the dancer commits. The existing bounded session duration makes this a natural match rather than a loss of continuity (src/people/hulaActivity.js:33; src/people/hulaSession.js:47).
- **Risk:** Too few families could become recognizable repetition. Preserve history/profile weighting and add new families through the same contract; do not advertise unrestricted invention. Interruption still needs a recorded entrance event, and dynamic obstruction must still cancel safely.
- **Effort:** Lower runtime control complexity than the boundary-by-boundary planner proposed in design.md:17, with comparable authoring effort for validated movements. Benchmark compilation separately because up to eight slots exist (src/people/hulaActivity.js:9,19), and do not move an unbounded search into construction.

A further inexpensive creative option is **performer identity through a seed-derived signature**, such as a recurring reversal or a long suspended isolation. Derive it from an existing stable person identity plus the new composition salt, keeping the current participant-selection path untouched. This is proposed behavior, not a claim that an appropriate stable public numeric identifier has already been established. Confirm that public contract before implementation; do not read Crowd's private records to obtain it. The activity currently selects through public handles and copied views (src/people/hulaActivity.js:65-70).

### Verdict

- **Verdict:** Proceed with mitigations.
- **Key Concern:** The plan risks investing in a general composition engine before demonstrating a short performance that reads as intentional at normal game distance.
- **Recommendation:** Preserve the full requested feature scope, make the first phrase and its returning motif the concrete creative gate, and simplify the initial composer into a bounded whole-session score compiler. Keep the minimal production adapter in the workshop milestone, then add the complete vocabulary, two-hoop counterpoint and partner exchange through the same tested contract. Current Vite guidance in AGENTS.md overrides the historical no-build prose in older council materials.
