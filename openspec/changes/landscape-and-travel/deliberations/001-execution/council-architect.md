## Architect's Position

### Priority Sequence

1. Complete Task 1.1 (integration baseline) and Task 1.2 (first-proof semantics), then start the pure contract immediately. The proposed dependency order correctly separates support, geometry, travel, admission and rollout, while current Vite policy requires ordinary imports rather than HTML inventories (`design.md:15–28`; `tasks.md:9–18`; `.claude/rules/no-build.md:15–19`).
2. Implement Group 2 (support/solid contracts) as a renderer-independent function over immutable descriptors and caller-owned mover state. Separate selecting/committing a transition from sampling an already selected surface; prove independent movers and nonmutating repeat queries before wiring the cart (`design.md:21`; `tasks.md:16–18`; `specs/landscape-travel/spec.md:27–37`).
3. Build Group 3 (authored engineering proof) through the existing terrain sandbox and real controller, with one fixture geometry source consumed by mesh construction and contact sampling. Add only the opt-in runtime binding needed for this proof, and keep legacy modes intact (`tasks.md:24–31`; `design.md:32–34`; `src/terrainSandbox.js:15–20,38–61`).
4. Complete Group 4 (authoritative travel) before district admission. The current drive gate checks a proposed center point, and collision resolution separately nudges X/Z, so a passing height query cannot establish a legal whole-cart final pose (`src/terrainDriving.js:41–45`; `src/collisionContacts.js:48–55`; `tasks.md:37–40`).
5. Implement one populated owner and prove teardown before procedural expansion, then add finite district/stream generation and migrate consumers. Keep device and player-recognition acceptance at rollout, as the finalized tasks require (`tasks.md:48–62,70–85,91–94`).

### Structural Risks Identified

- **Blocking correction before the cart proof: name the support-state commit boundary and its owner.** The design specifies current support/elevation, but Group 3 names fixture/sandbox ownership while runtime adapters and `terrainDriving.js` appear under Group 4. The existing controller calls the sampler for center, four wheels and repeated suspension corrections; movement also samples prospective positions before accepting them (`design.md:21,26`; `tasks.md:24–28,35`; `src/zerble.js:1228–1259,1279–1280`; `src/terrainDriving.js:11,43–45`). A sampler closure that commits support on any query can switch layers during a wheel probe or a rejected movement. Before Task 3.2 (landscape sandbox integration), specify a per-mover binding with explicit transition proposal/acceptance and layer-locked footprint samples, and explicitly assign its file ownership. This can fit a small adapter without converting every terrain consumer or changing the public controller contract.

- **Blocking correction before implementation of support failure behavior: make the failure result concrete.** Task 2.3 (support transition regressions) includes unknown/deleted support behavior, while the design promises terrain fallback and prohibits undeclared deck exits (`tasks.md:18`; `design.md:21`; `specs/landscape-travel/spec.md:35–37`). Task 1.2 (first-proof semantics) must distinguish initial acquisition from an invalid occupied support and define the returned blocked/error result, retained legal pose and reset/reacquisition path. Do not silently resolve a missing deck to terrain at the same X/Z. This is a required local contract decision, not a new product decision or a reason to delay the pure work.

- **Later integration gate: atomic admission must not imply transactional registry mutations.** The task calls for atomic admission/publication/disposal, but the project explicitly says registry mutations are not transactional (`tasks.md:48`; `AGENTS.md:102–104`). Before Group 5 (complete district), choose one owner key and an explicit staged-build/publication/rollback procedure that removes every owned registry entry, animation hook and allocated resource if a builder fails. A district spanning chunks needs one canonical content owner and separately pinned support dependencies, rather than duplicated per-chunk construction. Existing chunk-center ownership already builds complete clusters, and lake colliders intentionally survive chunk removal (`ARCHITECTURE.md:193–200,236–242`; `src/registry.js:50–52`). The authored fixture does not need this runtime owner system yet.

- **Later collision gate: preserve metadata through publication and candidate adapters.** Pure interval tests cannot establish that the live resolver receives intervals. The registry contract currently lists radius/damage, and its `colliders()` projection emits only position/radius/damage/kind; the resolver proceeds directly from X/Z overlap to response (`src/registry.js:50,128`; `src/collisionContacts.js:16–37`). Task 4.3 (vertical contact publication) must test the actual publication-to-resolver path with absent metadata retaining legacy behavior, below-deck exclusion, a spanning solid and unchanged ordered first-hit behavior (`tasks.md:39`; `design.md:26`). Keep this out of the first pure contract implementation.

- **Later geometry/generation gate: retain the acyclic planning split.** Current final terrain imports festival planning and creates zero-height venue pads, so the proposed landscape candidate module must not call that final sampler while deriving district foundations or routes (`src/worldgen/terrain.js:8,45,50`; `design.md:25,44,69`). Before Group 6 (procedural admission), record the concrete dependency direction from raw candidates through accepted grading to final shared geometry and append versioned deterministic expectations. The fixture's local triangulation is the correct initial scope; no global resolution increase is required (`design.md:23,34,76`; `tasks.md:59–62`).

### Verdict

- **Verdict**: Proceed with mitigations
- **Key Concern**: Support selection must not mutate mover state during prospective movement, wheel probes, ray verification or presentation.
- **Recommendation**: Start the baseline and pure contracts now. Resolve the two small contract/ownership corrections through the already required Task 1.2 (first-proof semantics) and before Task 3.2 (landscape sandbox integration). Owner rollback, live collider publication, procedural dependency proofs and device evidence are later acceptance gates, not prerequisites for this bounded first slice. Preserve the current generation baseline and concurrent physics/boot work throughout (`tasks.md:9–10,98–102`; `design.md:52–56`).
