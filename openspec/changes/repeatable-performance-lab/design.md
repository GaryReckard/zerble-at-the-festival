## Goals / Non-Goals

**Goals:** two trustworthy unattended desktop scenarios; script-owned analysis; immutable evidence; independent lifecycle safety; detection of a known injected cost; an agent skill around tested commands. Success means independently repeatable measurement, not a particular FPS target or an optimization shipped.

**Non-goals:** game optimization, user input recording, whole-world deterministic replay, general scenario DSL, automatic scheduling, mobile automation, cold-browser/driver cache guarantees, Auto-quality tuning and a general flight recorder. No new material, geometry, audio or world-ownership policy.

## Decisions

### 1. Separate collection, control and analysis

An opt-in `src/performanceLab/` module uses the existing main tick and capture timing, with a tiny explicit diagnostic input source in `src/input.js`. It must not create another game/render loop. Scenario modules are plain versioned data plus bounded progression functions, not a scripting language. Host control owns browser/server deadlines and capture acknowledgement. A pure Python analysis module serves the existing summary script and a proposed `bin/compare-perf-runs`; a proposed `bin/perf-lab` orchestrates execution. Names are planned interfaces, not commands that exist today.

Method-level `PeopleBaseline` wrappers and GPU timers are attribution reruns. Primary experiments reuse lightweight frame capture, exclude spawn probes, and declare instrumentation/version in every run. GPU timing is optional, bounded, disjoint-aware and absent rather than zero when unsupported. A blocked JS thread requires host cleanup; in-page finally is only the first defense.

### 2. Freeze app source and test harness separately

Use a small explicit inventory and two immutable app/build directories first, not a general snapshot-management framework. Before runs, capture explicit tracked content plus a bounded inventory of relevant untracked source/assets into a content-addressed snapshot outside the live checkout. Include dirty diff/untracked content hashes, dependency lockfile, build output hash and a common harness revision. Never sweep ignored captures, profiles, credentials or unrelated files into a snapshot; fail on undeclared runtime dependencies rather than guessing. Build and serve snapshot output using the current Vite pipeline, without HMR, on a task-owned loopback port, leaving port 8765 and the checkout untouched. Baseline and candidate have separate app identities; the harness, scenario and analyzer policy must be common. Preserve manifests before opening a browser.

Initial acceptance compares current-compatible unchanged snapshots and an explicitly injected variant; it requires no unrelated gameplay optimization. Arbitrary historical revisions and adapters are excluded from this milestone. Store local raw artifacts in ignored capture directories; promote selected evidence and a concise report to `verification/performance/<date>-lab/`.

### 3. Use one foreground hardware browser with structural ownership

After a minimum envelope/fixture, the first executable slice is an adapter feasibility spike and thin parked capture. Freeze one passing backend for this milestone, not two implementations. Preferred unattended backend is a single headed instance of installed full Chrome with a disposable test profile and loopback-only control, using the existing supported browser automation runtime where feasible. No headless-shell or SwiftShader measurements, no user-profile remote debugging, no disabling GPU/sandbox/security protections and no simultaneous WebGL systems. This standalone launch is justified by independent host deadlines and process ownership; it must pass the local safety harness before scenario expansion. A surviving supervisor owns the resource lease and control worker, retains a write-ahead ownership manifest, and enforces both loss-of-heartbeat and absolute deadlines. Killing the control worker must not kill its cleanup authority. Record pre-existing PIDs, task-created descendants and exact exit assertions; actual controller termination is an acceptance test. Do not rely on worker finally, inherited process-group teardown or page timers alone. A shared real-Chrome connector adapter is acceptable only with exact owned-tab closure, independent timeout enforcement and an explicit foreground/viewport capability; never require its shared GPU process to exit. Freeze the chosen backend identity for comparisons. Bootstrap the surviving bounded supervisor and exact resource ownership before the feasibility spike's first launch; finish blocked-page/control-worker-death proofs before expanding coverage. Unsupported automation is an explicit failed capability check, not a software-rendering fallback.

Each run opens the normal title, waits for readiness and performs its ordinary start gesture. Profile/storage initialization is confined to test-owned state. Install publication suppression and declared state before enabling the ready title plank, because start-time leaderboard/analytics calls precede audio initialization. Production progress/leaderboards/analytics are not published from lab sessions. Test state explicitly defines upgrades, mode, passengers/start conditions, bubble configuration and audio/mute policy. Install a neutral exclusive input owner in the first parked collection slice, covering every input channel, including camera/zoom/touch deltas and edge actions, while preserving only emergency abort. The streaming slice extends that same owner with route commands; it does not introduce input isolation for the first time. Settings or HUD mutations abort or invalidate measurement; restore held and edge state on every exit. Keep synchronous Sound.init in the click path. Reject console boot errors, unsupported initial footprint or missing scene readiness.

Gary's quiet-Mac assignment provides the experiment's operator attestation. No repeated permission prompts within that assignment; no scheduled follow-ups. Record known browser/game contention and visibility, plus available refresh/display/power facts without claiming unavailable thermal telemetry. Finish builds, tests and heavy analysis before timed runs; the runner must not compete with its own preparation work. The runner must not close/pause unrelated user tabs by assumption. If it detects an active competing session, refuse the measurement with an actionable reason unless session authorization already covers pausing it. A quiet attestation is not temperature telemetry or proof of OS isolation.

### 4. Start with two predeclared scenario manifests

`dense-festival-v1` uses a validated dry festival position at a fixed seed with naturally populated real content, ordinary bubbles and moving NPCs, pinned camera and time-of-day, separate settling, and a bounded measurement window. Initial candidate seed/pose comes from the existing measured High scene, but must be verified during implementation, not asserted as a permanent fixture. Define acceptable semantic population/content-policy/route bounds from unchanged-source runs, not a hardcoded requirement for identical live actor positions. Draw calls, submitted triangles, shader counts, resource counts and timings are implementation cost outcomes, not equality constraints. Reduced submissions with retained content remain eligible optimizations; undeclared reduced actor/content policy invalidates equal-work claims. Explicit visual/workload tradeoffs require a separate claim identity. Do not freeze NPCs, manipulate production RNG or equalize workload after seeing a result.

`streaming-drive-v1` uses a validated route on the same generation, initialized once before measurement. Logical throttle/steer/brake/boost follows accepted simulation progress, with ordered route checkpoints, corridor bounds and named outbound/turn/return segments. Normal suspension, collision, support admission and streaming remain active. No corrective teleport, bypassed collider or forced actor removal during measurement. If open-loop input proves too divergent, implement a bounded waypoint follower that still uses normal controller input, with a new versioned policy and recorded controls; compare like with like. Capture load/unload transitions from actual owners, completion wall time and segment coverage. Failure to complete is preserved as a workload failure and invalid performance comparison.

Initial caps: at most 20 accepted seconds for declared settling, 30 accepted seconds parked measurement, and 60 accepted seconds of driving; wall deadlines 90 seconds parked and 180 seconds driving including boot/settle. If calibration needs different budgets, change and version the manifest before candidate tests. Each host/browser command is bounded to at most 60 seconds; progress is emitted between commands, with a separate overall deadline. Startup/support wait never silently shortens the measurement window. Workload windows, cache preparation and prerequisites are declared; label this prepared-runtime steady/streaming coverage, not a cold browser benchmark.

### 5. Capture truth across clocks and source boundaries

Versioned run envelopes link existing device-capture records rather than duplicating their semantics. Current `FrameTelemetry.takeWindow` drains raw timing into window quantiles (`src/perfTelemetry.js:92`), so bounded exact-frame export is a new explicit implementation prerequisite. Keep those legacy window summaries labeled; never reconstruct run-level p95 from them. The primary lab buffer has a manifest-declared frame cap and a byte cap below the transport maximum; overflow fails the run rather than silently sampling away stalls. Required sections:

| Section | Contents |
| --- | --- |
| Identity | run/experiment ID, app and build hashes, harness/scenario/schema/policy versions, planned order, instrumentation, injection configuration |
| Conditions | GPU/browser/platform, viewport/DPR and actual canvas/composer/bloom dimensions, tier/rung/shadows/effects, seed/time/camera/start-state hash, mute and quiet-window attestation |
| Lifecycle | prepared, ready, settling, measuring, exporting, completed or failed/interrupted; timestamps, error and cleanup evidence; durable final hash/acknowledgement |
| Frames | real wall intervals and lightweight CPU work; bounded exact per-frame timings, never quantiles-of-quantiles presented as frame quantiles |
| Progress | raw outer elapsed, accepted gameplay elapsed, separately outer-clamped/physics-discarded time, physics-step/support waits, ordered checkpoints/segments and actual streaming events |
| Workload | population, registry, draw/triangle counts, program/resource counts and per-segment observations, with null/missing explicit |
| Diagnosis | optional method/GPU data under a separate instrumentation identity and unsupported/disjoint reasons |

Host creates the manifest first and captures state at boundaries, so page failure leaves a useful incomplete run. Bounded exports use the existing token-protected loopback path where feasible, enforce size/schema/path limits, use unique IDs and atomic writes, and acknowledge the exact final hash only after persistence. Retries of identical data are idempotent; conflicts fail. No capture can become complete because the browser says “done” before disk acknowledgement. Existing manual device captures retain parsing and report behavior; insufficient legacy metadata yields a readable legacy summary but cannot pass the new strict comparison contract.

### 6. Freeze analysis rules before candidate results

First measure incremental collector overhead using the same minimal timing sentinel in both modes. Buffer primitives during measurement, export afterward, and prohibit per-frame serialization/network/disk work or scene traversal. Share one authoritative owner of counter-draining reads (`src/debug.js:2043`); two consumers must not reset each other's evidence. Report overhead and its detection floor rather than claiming zero observer cost. Material overhead or workload perturbation blocks calibration.

Define one versioned policy containing metric definitions, quantile convention, stall thresholds (initial reporting at >50 ms and >100 ms), coverage checks, per-scenario workload tolerances, minimum repetitions and practical effect floors. Use raw frame timings for per-run/segment quantiles; never average p95s as global p95. Use independent runs as experimental units, retain totals and rates alongside elapsed/completed work, and retain all failures. Primary metrics are wall p95 and >50 ms stall rate; wall median/p99, >100 ms stalls, completion/time loss and resources remain visible guardrails.

Calibration uses at least four unchanged-source runs per scenario, split into two virtual labels in ABBA/BAAB order, to measure repeat-run spread. Freeze observed noise envelopes and practical floors in a calibration artifact tied to hardware/settings/scenario/harness. Start with conservative finite-sample rules: median run-level change must exceed both the frozen practical floor and maximum observed same-source spread, and the effect direction must agree in at least three of four paired comparisons. Do not claim statistical confidence from this rule. Validate the frozen policy on fresh unchanged-source holdouts, using two ABBA blocks with virtual source labels and no shared calibration samples. They must produce no detectable change with comparable work and no material drift; do not widen thresholds after seeing holdouts. Before launching a measurement experiment, display its explicit run inventory, accepted-time/settling budgets and wall deadlines. Full initial acceptance requires at least 40 calibration/holdout/injection runs across both scenarios, totaling 30 minutes of accepted measurement at the declared windows, with boot, settling, overhead checks and retries additional. This is a workload budget, not a wall-time promise; incomplete slices retain their narrower acceptance status. Actual baseline/candidate execution is two ABBA blocks with pair ordering defined in the policy, four runs per variant. If repeats are unstable or workload tolerances cannot be met, no improvement claim; revise the experiment and recalibrate, retaining prior attempts. Report contradictory order effects and reject material session drift under the frozen rule.

For each scenario, classify compatible data: a protected guardrail crossing its calibrated bound yields regressed (or invalid if comparability itself failed); improved requires improvement in a primary metric with no material protected regression; otherwise no detectable change. One scenario's gain cannot cancel another's regression. Suite result priority is comparison invalid, then regressed, then improved only if at least one improves and others show no detectable change, otherwise no detectable change. Always display scenario results and invalid/incomplete run counts. No arbitrary outlier deletion; show worst stalls even when medians improve. Proposed thresholds are measurement policy inputs requiring calibration, not established device budgets.

Diagnostic CPU injection is localhost-only, explicitly labeled and part of its variant identity. Configure bounded work at a known frame cadence and magnitude above the frozen noise floor and available wall-frame headroom; verify measured added CPU work independently from wall delivery; keep it out of startup, production and ordinary lab runs. Predeclare dose before the validation experiment. Both scenarios must detect a comparable injected candidate as regressed while fresh unchanged-source holdouts yield no detectable change. Insufficient wall sensitivity is a failed dose trial, not proof of broken statistics; retain it and redeclare/version a bounded dose before trying again. Route-invalid injection is failed validation, not successful regression detection. Never relax semantic bounds to make injection pass. Also verify missing metrics, null GPU, corrupt export, duplicates, reversed run order and mixed outcomes using fixtures. Reports carry exit codes distinguishing regression, invalid input and execution/cleanup failure; exact codes documented with implementation.

### 7. Put procedures in a skill, rules in code

Create a project-local `performance-lab` skill after commands and schemas stabilize, using the skill-authoring guidance at implementation time. It handles quiet-window prerequisites, backend choice, snapshot preparation, execution/status/export, analysis and evidence citation. It must not invent calculations, silently relax tolerances or infer “GPU-bound” from absent GPU data. Refer to one shared policy/schema implementation. Keep raw artifacts and source hashes sufficient for another agent to rerun the offline analysis without browser access.

## Risks / Trade-offs

- Shared hardware and thermal drift → reserved window, foreground checks, alternating repeats, observable session drift and limited hardware-specific claims; no automated proof of OS isolation.
- Live crowd/streaming variation → predeclared workload envelopes, per-segment evidence and invalid comparisons; do not solve whole-world determinism.
- Input/clock instrumentation alters ordinary behavior → opt-in hooks through current loop/controller, no production RNG/cadence changes, cleanup/restoration tests and normal-launch smoke.
- Browser/GPU resource leaks → independent host deadline and exact ownership assertions before adding coverage; abort on failure and preserve unrelated resources.
- Boot/audio/material regression → preserve synchronous gesture and shim, real main-game title-click smoke on Low/Mid/High, no new render passes or shadow casters.
- Snapshot or capture leaks unrelated files → explicit file inventory, loopback-only bounded transport, isolated storage, no user profile state or tokens in promoted evidence.
- Old toolchain language in OpenSpec → current AGENTS/Vite rules are authoritative; do not reintroduce importmap inventories. No existing seed regeneration or disposal policy change is planned.

## Migration Plan

Deliver three slices: (1) minimum envelope, one immutable build, supervised hardware browser and a thin active parked capture with exact frame export and interrupted-run proof; (2) collector-overhead evidence, full offline analyzer, parked calibration, fresh holdouts and injected-cost comparison; (3) normal-input streaming drive using the same capture path, its calibration/holdout/injection acceptance, complete failure coverage and skill/docs. A slice-one report says collection capability verified, not improved. The minimum surviving supervisor protects the first feasibility launch, and neutral all-channel input isolation is part of parked collection. Relevant project checks/build and ordinary plus diagnostic Low/Mid/High integration smoke precede each changed build's measurements and slice acceptance, even though the comprehensive checklist appears later. Each usable workflow slice updates CHANGELOG and its shipped ROADMAP scope in the same commit; the final documentation task does not defer this obligation. Both scenarios remain required for overall acceptance. Keep each stage independently testable and retain legacy manual capture support. Integrate the future implementation on an isolated branch/worktree after checking current Git state; this planning task leaves the existing dirty driving checkout intact. No seed migration, dependency upgrade or deployment is included.

## Construction recipe revision after a rejected full trial

`live-festival-v1` allowed the normal constructor’s eight independent 5–8-child draws. A normal run created 59 children outside calibration’s frozen upper bound of 58.3, so that trial remains invalid. `live-festival-v2` explicitly passes a private session-salted construction RNG to the same full child constructor before boot. Global Math.random is never replaced, live child behavior remains random and active, and ordinary play retains exactly its prior draws and 400-frame legacy behavior. No actor is removed or added to match a result. Initial population/layout is now part of the declared diagnostic fixture recipe, requiring entirely fresh overhead/calibration/holdout/injection data; prior bounds are not widened or reused. Appearance and live motion are not claimed deterministic.
