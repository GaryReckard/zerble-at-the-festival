## Synthesized Plan

### Change Group 1: Prove the measurement and browser foundation

**Scope:** A thin end-to-end parked capture that establishes feasibility, exact timing evidence and cleanup before a comprehensive analyzer or driving system.

**Estimated Effort:** One focused vertical slice, with separate feasibility and failure-proof checkpoints; duration depends on installed Chrome automation capabilities.

**Tasks:**

1. Define the minimum versioned run envelope and fixtures, including distinct app/build, harness/scenario, instrumentation and policy identities. Separate semantic workload inputs from implementation-dependent cost outcomes. Make raw per-frame timing a required lab capture field, with explicit bounded storage and missing-data semantics.
2. Freeze one passing foreground full-Chrome hardware backend and one initial fixed tier/rung/physical render size. Prove the ordinary ready-title start, isolated test state and pre-gesture publication suppression. Do not implement both browser backends or arbitrary historical-source adapters for this milestone.
3. Serve one immutable current-compatible source/build snapshot on an owned loopback port and run the active parked scene through the central tick, excluding attribution wrappers/spawn probes. Export exact frame timings with unique IDs, atomic persistence and final-hash acknowledgement. Preserve legacy guided report semantics.
4. Prove cleanup before expanding coverage: a surviving supervisor or bounded lease owns the standalone process tree independently of controller lifetime. Test blocked page JavaScript, actual controller termination, incomplete export and failed cleanup. Exact ownership must be established before launch, unrelated resources must survive, and any failed orphan assertion aborts further launches. A shared-browser adapter is eligible only if it provides an equivalent independent exact-tab cleanup contract.

**Exit evidence:** One acknowledged successful parked capture and one deliberately interrupted capture, both source-identified, plus exact resource cleanup. This means “collection capability verified”; it does not yet support an improvement verdict.

### Change Group 2: Calibrated analysis and the second scenario

**Scope:** Script-owned comparison rules grounded in real captures, then normal-controller streaming movement using the same proven collection path.

**Estimated Effort:** Two dependent slices: trusted parked comparison, then driving integration and repeatability.

**Tasks:**

1. Implement deterministic offline JSON/readable analysis from explicit capture paths. Derive per-run and segment quantiles from exact frames, retain individual-run units, preserve failures and distinguish invalidity from no detectable change. Do not derive run p95 from one-second p95 summaries or pool all frames across independent runs.
2. Measure collector perturbation before calibrating ordinary experiments. Use bounded buffered samples, no frame-by-frame serialization/network/disk/scene traversal, and one authoritative owner for counter-draining snapshots. Compare collector modes with the same minimal timing sentinel in both variants, document its limitations and reject material incremental overhead rather than claiming zero measurement cost.
3. Calibrate unchanged-source variation, freeze the finite-sample policy and workload tolerances, then validate it on fresh unchanged-source holdout runs that were not used to choose thresholds. Retain failed attempts and prohibit threshold widening after holdout/candidate results. Record observable refresh/display/power/session facts and invalidate material session drift; missing thermal telemetry remains an explicit limit.
4. Use the diagnostic CPU injection as the first candidate comparison. Declare dose/cadence after calibration, verify actual added CPU work, and ensure it crosses the relevant wall-frame boundary while preserving semantic workload and deadlines. An insufficient dose is an explicitly unsuccessful sensitivity trial; an invalid drive is failed lab validation. Redeclare/version the dose before another trial, without relaxing comparability. No unrelated optimization is required to prove the lab.
5. Extend to the streaming drive using exclusive logical input through the normal controller, truthful outer/accepted/physics clocks, ordered checkpoints and actual load/unload coverage. Own camera, zoom, edge actions and touch deltas as well as driving axes, with only deliberate emergency abort remaining live. Validate the route and repeat calibration, holdout and injection acceptance for this scenario. A versioned normal-input waypoint follower is the fallback if unchanged-source open-loop control cannot meet its predeclared corridor bounds; measured driving must never be corrected by teleport.

**Exit evidence:** A stable parked comparison and a stable driving comparison, each validated with independent unchanged-source data and a comparable injected regression. Full source snapshots, common-harness identity and paired run order are present from the first comparative claim, but no general snapshot-management framework is required.

### Change Group 3: Quality and failure acceptance

**Scope:** Prove that the lab detects the intended cost while preserving ordinary game behavior and honestly rejecting bad experiments.

**Estimated Effort:** Bounded automated fixtures plus reserved-Mac experiments; build/test work completes before timed captures.

**Tasks:**

1. Test semantic invariants versus outcomes: lower draw calls/submitted triangles/program/resource costs with preserved content remain comparable, while undeclared reduced crowd/content policy invalidates an equal-work claim. Explicit quality/workload-tradeoff experiments receive a separate claim class and cannot silently count as equal-content improvements.
2. Test exact-frame quantiles, duplicate/incomplete/corrupt reports, absent/disjoint GPU timing, configuration/instrumentation mismatches, held-out drift, mixed protected metrics, genuine CPU increases without wall change, and comparable wall regressions. Unsupported GPU queries do not invalidate otherwise valid CPU/frame evidence.
3. Prove state/input restoration and publication isolation at their real boundaries. Lab sinks/state must exist before the ready title gesture, because current leaderboard/analytics start calls precede `Sound.init()` (`src/main.js:1033-1077`). Do not insert an awaited setup step into that synchronous gesture. HUD/settings interactions that alter conditions abort or invalidate the run.
4. Run project checks/build and ordinary plus diagnostic ready-title game smoke on Low/Mid/High. Inspect real render settings, console and post-run residual activity. The initial measured configuration is one fixed tier, while other tiers receive integration smoke until separately calibrated. No seed regeneration, geometry/shadow addition or world-disposal change belongs in this milestone.
5. Produce the acceptance bundle: calibration, fresh holdouts, alternating baseline/injected candidate blocks for both scenarios, collector-overhead evidence, incomplete-attempt records, exact cleanup assertions and deterministic regenerated analysis. Verdicts are improved, regressed, no detectable change or comparison invalid, with scenario-level results and preserved worst stalls. Do not run builds, full tests or other heavy analysis concurrently with measurement.

**Exit evidence:** Both scenarios satisfy collection, sensitivity, repeatability and lifecycle gates. A quiet-Mac assignment is recorded once for the experiment and is not a claim of OS-wide isolation. Desktop results do not establish mobile performance, subjective driving feel, cold-cache behavior or Auto quality acceptance.

### Change Group 4: Agent handoff and documentation

**Scope:** Make the verified procedure repeatable for the next agent without turning prose into a second analyzer.

**Estimated Effort:** One documentation/skill handoff after commands and evidence stabilize.

**Tasks:**

1. Write the project-local performance-lab skill around the verified backend, runner and analyzer commands. Scripts own schema, statistics, compatibility and verdict rules; the skill owns prerequisites, execution order, cleanup, evidence citation and interpretation limits.
2. Update DEBUGGING, the performance playbook, documentation/verification indexes, CHANGELOG and ROADMAP, retaining existing manual phone/desktop workflows. Describe the three usable delivery slices: collection-only parked, trusted parked comparison and accepted two-scenario lab.
3. Verify delta-spec coverage, refresh README/session state and preserve a compact report with raw artifact/source identities. Keep scheduling, flight recording, broad matrices, historical adapters and mobile automation outside this change.

## Final Recommendation

**Proceed with mitigations, after folding these refinements into design, delta requirements and tasks.** Start with a minimum contract and independently supervised parked capture, then build calibrated analysis from actual exact-frame data, and finally extend the same path to driving. The two-scenario milestone remains intact, but no large analyzer or snapshot framework should precede proof that the only hardware-browser collection path works and tears down safely.

---

## Convergence Points

- All three personas support the two distinct workloads, fixed settings, immutable source identity, retained failures, one hardware backend and a skill around tested scripts.
- All reject software-WebGL performance verdicts, paused-world scene probes as ordinary gameplay measurements, silent exclusion of divergent runs and expansion into whole-world determinism or mobile automation.
- All support calibrated thresholds before candidate claims and independent browser deadlines. The synthesis strengthens those into fresh holdout validation and supervision that survives controller death.
- All distinguish semantic work from cost outcomes: fewer renderer submissions can be a successful optimization, while silently rendering less festival content is a different claim.
