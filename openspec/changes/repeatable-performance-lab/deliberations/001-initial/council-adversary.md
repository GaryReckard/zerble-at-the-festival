## Adversary's Position

### Priority Sequence

1. Prove the host/browser safety boundary first, including controller death and not just a blocked page. A run is not safe because its successful path closes Chrome. The local instructions explicitly require structural deadlines, exact process ownership and failure-path orphan assertions (`AGENTS.override.md:17-25`).
2. Implement the run contract and offline invalid-input tests before claiming comparative results. Preserve distinct app, harness, scenario and measurement identities, and keep complete-work evidence separate from performance outcomes (`design.md:23-25`, `design.md:49-57`).
3. Calibrate on unchanged-source runs, freeze the policy, and validate it on fresh unchanged-source holdout runs before the injected regression. Do not use the same observations to define a maximum noise bound and then announce that those observations fit it (`design.md:63-67`).
4. Land opt-in input/loop hooks, then the active parked scenario, then streaming. Verify ordinary Low/Mid/High title-click boots and complete restoration before doing the full measurement matrix (`tasks.md`, sections 3-5).
5. Add the skill only around scripts and lifecycle paths that have passed these checks. No claim about mobile audio or player feel follows from a desktop timing report.

### Vulnerabilities Found

- **Controller death can outlive the proposed host deadline.** The plan correctly moves cleanup outside the page, but a deadline owned only by the same controller process can disappear when that controller is killed or its automation call blocks. Task 2.4 (failure-injection harness) names controller interruption but does not define a surviving supervisor. For standalone Chrome, require a separate bounded supervisor/lease that owns the process tree and survives controller exit; test actual controller termination as well as page-thread hangs. Verify all recorded task-created descendants by exact PID, and fail closed if ownership cannot be established. Never use a global Chrome kill. This sharpens the existing independent-deadline promise rather than adding a second browser system (`design.md:29`, `tasks.md:12-13`, `AGENTS.override.md:17-25`). Severity: **High**.

- **Repeatability acceptance is partly circular without held-out runs.** The current design derives the maximum same-source spread from four runs, then expects ordinary unchanged-source data not to produce a directional result. If that is the same dataset, passing is largely built into the threshold. Reserve fresh unchanged-source runs after policy freeze and require their A/A verdict to be no detectable change, with matching workload and no drift. Record calibration and validation identities separately, and do not widen thresholds after seeing holdout or candidate failures (`design.md:63-67`, `tasks.md`, section 5). Severity: **High**.

- **Workload equivalence can accidentally prohibit the optimization being tested.** The design records population, draw calls, program/resources and streaming counts, but does not yet separate invariant scenario work from implementation-dependent cost. For example, the bubble fix removed a duplicate scene render while retaining the visible scenario; exact draw-count equality would invalidate the very improvement the lab should detect. Define semantic work invariants, such as route/checkpoints, content/people policy and required load/unload coverage, separately from outcome/cost counters, such as draws, submitted triangles, programs and resource count. Resource growth can be a guardrail, but cost reductions must remain comparable when semantic work is preserved. Existing evidence demonstrates this distinction (`verification/performance/2026-11-02-render-load/README.md:9-20`; proposed `design.md:37`, `design.md:54`, `design.md:65`). Severity: **High**.

- **Overriding driving axes alone does not make an exclusive session.** Input also exposes camera axes, touch camera deltas, zoom and edge-triggered actions; the main loop can change camera mode, cart visuals, map and music independently of throttle/steering. The exclusive adapter needs an explicit policy for every channel, retaining only an intentional emergency abort, and tests proving restoration of both held and edge state. HUD/pointer interactions that mutate settings should invalidate or abort the measurement rather than silently alter it (`src/input.js:69-93`, `src/input.js:117-137`, `src/main.js:1327-1351`; proposed `tasks.md`, section 3). Severity: **Medium**.

- **Startup isolation must precede the real title gesture.** Lab-only state and publication guards cannot be installed asynchronously after the click. The existing start callback calls leaderboard and analytics before synchronous `Sound.init`, and existing capture starts only after that sound initialization. Install predeclared diagnostic sinks/state before enabling the title plank, preserve the normal synchronous click callback, and avoid adding an awaited lab setup stage inside it. A disposable test profile protects Gary's stored preferences but does not by itself suppress network publication (`src/main.js:1033-1077`, `src/sound.js:271-350`; proposed `design.md:31`, `tasks.md`, section 3). Severity: **Medium**.

- **Injected work may invalidate a drive rather than produce a comparable regression.** The physics clock can discard time when support is blocked, while the outer frame clamp has already removed other time. A large injection can change route completion or residency enough to violate comparability. Predeclare a bounded injection dose above the calibrated detection floor that still completes both scenarios; treat invalid injection runs as failed lab validation, not as successful regression detection or a reason to relax workload bounds. Schedule control progression against an explicit clock and record the other clocks as planned (`src/main.js:1207`, `src/physics/fixedStep.js:9-25`, `src/physics/liveWorld.js:340-342`; proposed `design.md:39`, `design.md:67`). Severity: **Medium**.

### Constraints Already Handled Correctly

The plan correctly retains real-game updates during parked measurement, marks GPU timers optional, rejects software rendering, separates exact shared-tab ownership from standalone process ownership, protects Gary's play server/profile, and does not assume hidden tabs are idle. The engine explicitly keeps hidden tabs ticking (`src/main.js:1942-1947`). It also follows current Vite/module instructions rather than obsolete importmap rules (`.claude/rules/no-build.md:12-25`), preserves the Three shim (`src/threeShim.js:1-23`), and declares no seed/order or world-disposal change. These constraints should remain requirements, not implementation conveniences.

### Verdict

- **Verdict**: Proceed with mitigations.
- **Key Concern**: A trustworthy result requires independently enforced cleanup and independent validation data; both can appear to work on a happy path while failing the unattended use case.
- **Recommendation**: Keep the two-scenario scope, and fold supervisor survival, held-out A/A validation, semantic-versus-cost comparability, complete input ownership and pre-gesture isolation into the first milestone. Do not widen the scope to mobile, full-world determinism, a recorder or extra quality matrices before those gates pass.
