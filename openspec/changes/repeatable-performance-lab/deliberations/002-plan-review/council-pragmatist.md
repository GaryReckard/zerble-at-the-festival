## Pragmatist's Position

TL/DR: Retain the three-slice plan and its acceptance contract, but pull the neutral-input ownership part of the driving adapter into the first parked slice. The strongest force multiplier is proving one independently supervised, hardware-backed browser can produce an acknowledged real-game capture and clean up after a dead controller before investing in comparison or route logic.

### Critical Path

The sequential dependency is minimum envelope → hardware-browser feasibility → immutable build and independent supervisor → thin active parked capture → collector-overhead check → calibration and fresh holdouts → injected-cost sensitivity → normal-input streaming and its own acceptance. The design already chooses this order and makes collection capability distinct from performance acceptance, so neither a streaming controller nor a game optimization should block the first useful result (`openspec/changes/repeatable-performance-lab/design.md:29`, `openspec/changes/repeatable-performance-lab/design.md:87`; `openspec/changes/repeatable-performance-lab/tasks.md:14`, `openspec/changes/repeatable-performance-lab/tasks.md:23`).

The one sequencing correction is input ownership. Task 4.1 (exclusive logical input adapter) currently sits after trusted parked comparison, although the spec requires exclusive ownership during either scenario and the first slice promises a declared parked pose and camera (`openspec/changes/repeatable-performance-lab/tasks.md:27`; `openspec/changes/repeatable-performance-lab/specs/performance-lab/spec.md:9`, `openspec/changes/repeatable-performance-lab/specs/performance-lab/spec.md:21`). Split that task: implement the neutral parked source, all-channel exclusion, emergency abort and exit restoration with Task 2.1 (opt-in main-loop hooks), then add non-neutral route commands in the driving group. This is an ordering correction within existing scope, not a request for a broader input framework.

The existing guided parked lock cannot establish this contract by itself: the main loop chooses neutral driving input under `captureDriveLocked`, while camera-mode edge actions still consume `Input` separately (`src/main.js:1266`, `src/main.js:1327`). The facade also exposes touch camera deltas and zoom separately from throttle/steering (`src/input.js:97`, `src/input.js:129`, `src/input.js:136`). Explicitly test these channels before accepting the parked slice.

### Priority Sequence

1. **Prove the risky external capability first.** Complete the minimum envelope and one hardware-backed installed-Chrome adapter, then demonstrate blocked-page and actual control-worker termination cleanup before expanding browser coverage. This follows Tasks 1.1 through 1.4 (minimum contract and supervised foundation), and directly addresses the documented failure in which cleanup code alone does not prove safe failure handling (`openspec/changes/repeatable-performance-lab/tasks.md:3`; `openspec/changes/repeatable-performance-lab/tasks.md:6`; `docs/browser-verification.md:23`). Freeze the first passing backend rather than adding alternatives (`openspec/changes/repeatable-performance-lab/design.md:29`).
2. **Build the smallest trustworthy collection path.** Use one immutable current-compatible build, the central tick, early isolated state/publication suppression, the neutral exclusive input source, bounded frames and an acknowledged export. Existing telemetry is reusable timing plumbing, but `takeWindow()` clears the frame array and returns summaries, so exact per-frame export is real prerequisite work rather than an analyzer-only change (`src/perfTelemetry.js:92`; `openspec/changes/repeatable-performance-lab/tasks.md:10`; `openspec/changes/repeatable-performance-lab/tasks.md:12`). The current Vite transport checks origin and size but writes directly to the final filename, so atomic/idempotent hash acknowledgement needs the explicit transport work already assigned to Task 2.3 (bounded run export), not an assumption that the upload path is finished (`tooling/capture.mjs:17`, `tooling/capture.mjs:33`; `openspec/changes/repeatable-performance-lab/tasks.md:12`).
3. **Use saved data to make analysis cheap.** Implement parser/analyzer fixtures independently of later route construction, retaining the guided-report semantics. The current summary takes medians of window p95 values, which remains a readable manual summary but cannot become a raw-frame run p95 (`bin/report-perf-playtest:83`, `bin/report-perf-playtest:87`; `openspec/changes/repeatable-performance-lab/tasks.md:18`). This offline path is the force multiplier for subsequent investigation because another agent can regenerate results without reopening Chrome (`openspec/changes/repeatable-performance-lab/specs/performance-lab/spec.md:101`, `openspec/changes/repeatable-performance-lab/specs/performance-lab/spec.md:137`).
4. **Spend the reserved Mac window only after preparation passes.** Collector overhead precedes calibration; fresh holdouts precede candidate sensitivity. Preserve the existing instruction in Task 5.3 (tier integration and production inactivity checks) that builds/tests complete before timed measurements, and make it a dependency of the earlier timed tasks rather than reading group numbers as permission to postpone it (`openspec/changes/repeatable-performance-lab/tasks.md:21`; `openspec/changes/repeatable-performance-lab/tasks.md:22`; `openspec/changes/repeatable-performance-lab/tasks.md:37`). This is already a stated validation requirement, not a missing test.
5. **Add driving after the parked chain works.** Keep the explicit open-loop feasibility test and bounded normal-input waypoint fallback. Route instability is an implementation experiment already assigned its own task, not a reason to block the plan or require deterministic crowd replay (`openspec/changes/repeatable-performance-lab/tasks.md:29`; `openspec/changes/repeatable-performance-lab/tasks.md:30`). Separate wall and accepted simulation clocks are necessary because the actual fixed-step clock can discard elapsed time, including when support is unavailable (`src/physics/fixedStep.js:11`, `src/physics/fixedStep.js:18`).

### Delivery Cost and Acceptance

The proposed repetition burden is meaningful but bounded: the minimum four calibration runs, eight fresh holdout runs and eight injection runs total twenty runs per scenario before overhead experiments, retries or insufficient-dose trials. That is forty runs for the two-scenario gate, derived from the declared four calibration runs and two ABBA blocks for each validation stage (`openspec/changes/repeatable-performance-lab/design.md:65`, `openspec/changes/repeatable-performance-lab/design.md:69`). At the declared 30-second parked and 60-second driving measurement caps, this is thirty minutes of accepted measurement, with boot, settling, overhead trials and analysis additional (`openspec/changes/repeatable-performance-lab/design.md:41`). The runner should show the planned run inventory before reserving the measurement window; there is no justification for shrinking the acceptance contract just to make the run look shorter.

The first candidate being a declared injected slowdown is a good scope decision because it proves the lab without coupling delivery to an unrelated optimization. Dose insufficiency and route-invalid injection already have explicit failed-validation outcomes, so those are implementation questions with assigned experiments, not omissions requiring more planning (`openspec/changes/repeatable-performance-lab/tasks.md:23`, `openspec/changes/repeatable-performance-lab/tasks.md:31`; `openspec/changes/repeatable-performance-lab/specs/performance-lab/spec.md:119`).

### Deferred / Park on ROADMAP

- **Backend expansion, historical-revision adapters and snapshot frameworks:** Keep one passing backend and current-compatible immutable snapshots; neither comparison nor driving depends on a general version-management system (`openspec/changes/repeatable-performance-lab/design.md:23`, `openspec/changes/repeatable-performance-lab/design.md:25`, `openspec/changes/repeatable-performance-lab/design.md:29`).
- **Scheduling, whole-world replay, a general flight recorder and broad quality/mobile matrices:** Retain their explicit exclusions because the lab can establish repeatability and sensitivity for one desktop configuration without them (`openspec/changes/repeatable-performance-lab/design.md:11`; `openspec/changes/repeatable-performance-lab/README.md:45`).
- **The operating skill until commands stabilize:** Retain this timing because scripts own the result, while the skill packages the verified procedure. The skill is still required for final acceptance (`openspec/changes/repeatable-performance-lab/design.md:73`; `openspec/changes/repeatable-performance-lab/tasks.md:42`).

### Incremental Delivery Plan

- **Slice 1 (ship first): Safe real-game collection.** Complete groups 1 and 2, plus the extracted neutral exclusive-input work and relevant ordinary-launch/integration checks. Save one successful acknowledged active-festival capture, one interrupted capture and independent cleanup proofs, and label the result collection capability verified. This enables offline development using real fixtures without implying comparison acceptance (`openspec/changes/repeatable-performance-lab/tasks.md:6`, `openspec/changes/repeatable-performance-lab/tasks.md:14`; `openspec/changes/repeatable-performance-lab/design.md:87`).
- **Slice 2 (ship after): Trusted parked comparison.** Reuse Slice 1 artifacts and runner for analyzer fixtures, overhead, calibration, separate holdouts and declared injected sensitivity. Its accepted claim is parked comparison on the recorded hardware/settings, with no driving claim (`openspec/changes/repeatable-performance-lab/tasks.md:18`; `openspec/changes/repeatable-performance-lab/tasks.md:23`; `openspec/changes/repeatable-performance-lab/design.md:87`).
- **Slice 3 (complete milestone): Streaming and agent handoff.** Extend the same input owner with route commands, add truthful progress/streaming evidence and driving-specific acceptance, then finish failure coverage, the operating skill and documentation. Both scenarios remain mandatory for the completed lab (`openspec/changes/repeatable-performance-lab/tasks.md:28`; `openspec/changes/repeatable-performance-lab/tasks.md:38`; `openspec/changes/repeatable-performance-lab/tasks.md:42`).

### Verdict

- **Verdict**: Proceed with mitigations.
- **Key Concern**: Exclusive input ownership is scheduled in the driving group even though the parked slice already requires it.
- **Recommendation**: Retain the scope, three slices and conservative acceptance contract; split Task 4.1 (exclusive logical input adapter) so neutral all-channel ownership and restoration precede the first parked acceptance, and make the already-required pre-measurement build/integration checks explicit dependencies. No additional feature or benchmark matrix is needed.
