### Experience Concerns

- **Player:** The proposed workload preserves the experience the lab is intended to protect. It keeps NPCs and bubbles alive, measures real controller driving with suspension/collision/streaming, and treats reduced crowd content as a different experiment instead of an automatic improvement. The player premise is a living festival with bubble and crowd reactions, so this distinction matters more than holding draw-call totals constant (repository `README.md:9`, `README.md:22`; `design.md:37`, `design.md:39`; `specs/performance-lab/spec.md:85`). The lab also protects ordinary play through opt-in activity and input restoration, with actual production-path smoke tests assigned rather than assumed (`specs/performance-lab/spec.md:17`, `specs/performance-lab/spec.md:21`; `tasks.md:37`).
- **Next agent / dev:** This is the appropriate equivalent of a sandbox for an integration measurement. Project doctrine explicitly places streaming and collision in the running game, while the plan turns those emergent behaviors into named, bounded scenarios and provides offline reanalysis from saved evidence. A new entity viewer would not exercise the behavior being measured (`.claude/rules/sandbox-and-testing.md:133`; `design.md:17`, `design.md:39`, `design.md:73`). Exact-frame capture is correctly treated as new work: the existing telemetry drains its window and returns summaries, which are insufficient for a later whole-run frame percentile (`src/perfTelemetry.js:92`; `design.md:45`; `tasks.md:11`).
- **Cognitive Load:** There are many evidence fields, but the plan puts their authority in scripts and exposes four fixed verdicts, lifecycle states and three delivery slices. It avoids making every operator learn a scenario language or implement statistical rules. This is a useful division of responsibility provided the later skill uses the verified commands as specified (`design.md:17`, `design.md:51`, `design.md:67`, `design.md:73`, `design.md:87`; `specs/performance-lab/spec.md:133`). The once-per-experiment quiet-window attestation also respects Gary's assignment without adding repeated permission interruptions (`specs/performance-lab/spec.md:49`).
