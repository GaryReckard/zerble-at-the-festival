### Quality Deficiencies Found

- **Exclusive input is scheduled after trusted parked comparisons. Severity: Medium.** The requirements apply exclusive driving, camera, zoom, touch and edge-action ownership throughout a scenario, and the design likewise requires every input channel to be owned (`openspec/changes/repeatable-performance-lab/specs/performance-lab/spec.md:21`, `openspec/changes/repeatable-performance-lab/design.md:31`). However, the explicit implementation and no-mixing test sit in Task 4.1 (exclusive logical input), after Task 3.5 (parked calibration and holdouts) and Task 3.6 (parked injection validation), while the migration plan calls the preceding slice a trusted parked comparison (`openspec/changes/repeatable-performance-lab/tasks.md:22`, `openspec/changes/repeatable-performance-lab/tasks.md:23`, `openspec/changes/repeatable-performance-lab/tasks.md:27`, `openspec/changes/repeatable-performance-lab/design.md:87`). This is a real dependency gap because the current capture driving lock only selects neutral driving input, while view and map edge actions still consume the live Input facade (`src/main.js:1266`, `src/main.js:1327`, `src/main.js:1349`). Move neutral ownership, restoration and mutation invalidation into the parked slice, with a parked test that keyboard/touch actions cannot silently change conditions. The later driving task can extend that owner with nonzero scripted controls.

- **The documentation task does not state the same-commit rule for independently delivered slices. Severity: Low.** Task 6.2 (documentation and workflow records) includes CHANGELOG and ROADMAP, but the design deliberately delivers three independently testable slices (`openspec/changes/repeatable-performance-lab/tasks.md:43`, `openspec/changes/repeatable-performance-lab/design.md:87`). Project policy forbids batching changelog updates across commits and explicitly includes development-workflow changes (`.claude/rules/changelog-and-roadmap.md:8`, `.claude/rules/changelog-and-roadmap.md:21`). Add a task-level delivery note that every commit shipping a usable workflow slice updates CHANGELOG and trims only the corresponding shipped ROADMAP scope. Task 6.2 (documentation and workflow records) should remain the comprehensive final documentation pass rather than imply deferred commit hygiene.

### Existing Patterns and Verification Coverage

The reuse audit is sufficiently broad for this milestone. It identifies guided capture, upload/build transport, intrusive PeopleBaseline attribution, the paused scene probe, sandbox replay, main/physics clocks and browser ownership, and it states how each is reused or excluded (`openspec/changes/repeatable-performance-lab/proposal.md:32`). It does not need a sweep across unrelated model implementations because graphics and world-ownership changes are excluded (`openspec/changes/repeatable-performance-lab/design.md:11`).

Two implementation prerequisites are accurately recognized rather than hidden behind reuse language. `FrameTelemetry.takeWindow()` drains its raw frame window into aggregates, so strict run quantiles require the new bounded exact-frame path; `collectPerfSample()` also drains the crowd timing window, which requires a single owner (`src/perfTelemetry.js:92`, `src/debug.js:2043`, `openspec/changes/repeatable-performance-lab/tasks.md:11`). Existing Vite capture middleware writes directly to the final filename and acknowledges a byte count, so the new atomic/idempotent/final-hash export is additional implementation work already assigned to Task 2.3 (durable acknowledged export), not an assumed existing capability (`tooling/capture.mjs:33`, `tooling/capture.mjs:34`, `openspec/changes/repeatable-performance-lab/tasks.md:12`).

Browser feasibility, actual route stability, raw-data cap sizing and observer overhead remain explicit implementation validations, not reasons to block planning. Their tasks provide failure gates rather than authorize software-rendered fallback, corrective teleports or material instrumentation perturbation (`openspec/changes/repeatable-performance-lab/tasks.md:3`, `openspec/changes/repeatable-performance-lab/tasks.md:4`, `openspec/changes/repeatable-performance-lab/tasks.md:21`, `openspec/changes/repeatable-performance-lab/tasks.md:30`).

### Verdict

- **Verdict**: Proceed with mitigations
- **Key Concern**: The parked slice promises trusted comparison before the checklist explicitly installs and tests exclusive input ownership.
- **Recommendation**: Retain the architecture and acceptance contract, move neutral input protection into the parked slice, annotate safe first-launch prerequisites, and make same-commit documentation discipline explicit for every shipped slice. These are ordering and delivery clarifications, not a broader milestone.
