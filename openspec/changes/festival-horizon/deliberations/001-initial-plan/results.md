# Deliberation Summary

## Context
-   **Task**: Determine whether the bounded, render-only festival horizon is safe and sufficiently scoped to implement, and identify required changes to the finalized OpenSpec plan.
-   **Personas Consulted**: Architect, Profiler, Adversary, and Mediator
-   **Date**: 2026-08-26

## Synthesized Plan

### Change Group 1: Harden the Contract and Build the Measurement Surface
**Scope**: Close the ownership, worldgen-mode, scheduling, resource-lifetime, and budget gaps before Three.js renderer work. Move the isolated shell and baseline measurements ahead of the visual implementation, combining the Architect's harness-first order with the Profiler's measure-first order and the Adversary's contract-first requirements (`council-architect.md:5-9`; `council-profiler.md:5-11`; `council-adversary.md:5-10`).
**Estimated Effort**: 1-2 focused sittings.
**Tasks**:
1. Amend `proposal.md`, `design.md`, the delta spec, and `tasks.md` so effective enablement is `farFieldRequested && USE_WORLDGEN_V2`; cached worldgen descriptors are immutable inputs; initial ownership snaps without animation; reduced motion is read live; and the default-off path performs zero FarField allocation or shader-program creation. Reconcile the stale canonical lifecycle claim by narrowing `worldgen-layout` persistence to render-agnostic query tuples while festival cluster ownership follows the existing descriptor-center contract (`council-adversary.md:14-15,21,23`; `council-architect.md:17,23`; `openspec/specs/worldgen-layout/spec.md:161-170`; `openspec/specs/festival-composition/spec.md:109-120`).
2. Export one pure half-open owner-cell helper from `src/worldgen/placement.js`, add a narrow `ChunkManager.isLoaded(cx, cz)` predicate, and keep the private chunk-key format out of `FarField`. Lock positive, negative, edge, and corner fixtures before integration (`council-architect.md:13`; `council-adversary.md:18`).
3. Define one world-owned streaming deadline. Real chunk work runs first, FarField receives only the remaining time, and versioned pending jobs must be superseded by newer player cells. The contract must cover descriptor discovery, candidate preparation, pool rewrite, bounds calculation, and upload preparation, while measuring the largest indivisible cold call separately (`council-architect.md:15`; `council-profiler.md:43-46`; `council-adversary.md:16`).
4. Scaffold the hub-sandbox horizon shell, deterministic fixtures, fake loaded-state predicate, explicit teardown, and resource counters. Capture fixed-pose disabled baselines on real `?perf=low|mid|high` reloads, then cold-benchmark representative dense seeds before geometry. Pin per-tier instance, road vertex/index, upload-byte, and submitted-triangle maxima, using provisional marginal caps of +5k triangles on low and +10k on mid/high until measurement justifies tighter values (`council-architect.md:6`; `council-profiler.md:36-39,43-45`).

### Change Group 2: Implement the Opt-In Render Peer
**Scope**: Build a deterministic, fixed-capacity `FarField` peer with no gameplay ownership, starting with the cheapest visual vocabulary and adding the remaining batches only while measured caps hold. The group is independently safe to land because production behavior remains unchanged without `?farField=1` (`design.md:47-80,122-128`; `specs/festival-horizon/spec.md:23-47,148-153`).
**Estimated Effort**: 3-5 focused sittings.
**Tasks**:
1. Implement a pure, non-mutating planner that copies public descriptors into compact records with stable identities, deterministic tie-breaks, owner coordinates, and loaded-state-independent capacity selection. Rebuild only on 80m cell changes or explicit debug requests, and prevent an older pending snapshot from committing after a rapid teleport (`council-architect.md:19`; `council-adversary.md:7,15-16`).
2. Implement FarField-instance-owned fixed buffers for the road, stage canopy, and roof peaks first. Keep the peer root outside chunk, lake, and hub-preview disposal trees; allocate once; rewrite in place; update active counts and every matrix/color/fade flag; recompute bounds after every commit; and make `dispose()` detach and release owned resources exactly once even when called twice (`council-profiler.md:8`; `council-architect.md:21`; `council-adversary.md:8,19,22`).
3. Build the road as a deterministic clipped ribbon at an explicit elevation strictly above the ground and below the authoritative road's `y=0.06`. Preserve a narrower footprint and compatible depth behavior so the real road covers it without z-fighting (`council-adversary.md:17`; `specs/festival-horizon/spec.md:109-113`).
4. Add the proxy-only opaque Bayer handoff with one stable shader source and cache key per actual variant. Use data or uniforms for runtime changes, bounded fade-attribute update ranges, a live reduced-motion getter, and direct hidden initialization for already-loaded owners. Add trusses and the two night-marker batches only if draw, triangle, culling, upload, and program-count measurements remain green (`council-profiler.md:8-10,47-48`; `council-adversary.md:9,20-21`).
5. Integrate the peer through `world.js` after authoritative chunk updates, using the narrow loaded predicate and remaining shared deadline. Add the default-off/v2-only flag resolution, all four HTML cache-buster entries, isolated and full-game debug controls, and no registry, builder, collider, crowd, audio, real-light, shadow, or per-prop animation dependencies (`council-architect.md:8,25`; `council-adversary.md:5,9`; `tasks.md:9-11`; `specs/festival-horizon/spec.md:23-35`).

### Change Group 3: Prove Correctness, Portability, and Budgets
**Scope**: Exercise the cheapest surfaces first, then prove the game-only lifecycle and render path under every relevant mode. Sandbox tier controls are composition previews only; real tier and `threeShim` behavior must be tested through page reloads (`council-adversary.md:20`; `tasks.md:55-72`).
**Estimated Effort**: 2-3 focused sittings plus bounded browser captures.
**Tasks**:
1. Complete `bin/test-far-field` with descriptor pre/post hashes or deep-frozen fixtures, byte-identical repeated output, fixed-capacity estimators, exact negative owner boundaries, v1 no-op, rapid-job supersession, registry/RNG identity, second-distant-rewrite bounds, bounded update flags, repeated dispose, and stable resource counts. Run `npm run check`, focused tests, layout lint, importmap checks, static syntax checks, and `git diff --check` (`council-adversary.md:14-19,22`; `tasks.md:51-59`).
2. Verify proxy-only, real-only, and handoff views at Noon and Midnight in the hub sandbox, including overflow and resource panels, composition at simulated tier settings, camera-facing-away culling, and grazing-angle road coverage. Reload the sandbox separately with `?perf=low|mid|high` to prove actual tier and shader paths (`council-profiler.md:25,47`; `council-adversary.md:17,20`).
3. Boot the real title and start flow with the flag absent and enabled on low, mid, and high, plus `?worldgen=0&farField=1`. Exercise mobile viewport, live reduced-motion changes, hidden-tab continuation, rapid multi-cell teleport, load/unload/reload of the same owner, recentered-ground travel, and WebKit or Safari shader compilation. Confirm clean console output, unchanged synchronous audio start adjacency, and no ghost proxy over already-loaded chunks (`council-adversary.md:9-10,14,17,20-23`; `council-architect.md:9,23`).
4. Run repeated fixed-pose and long-travel A/B/A captures. Record absolute and marginal draws and submitted triangles, parked p95 and worst frame time, boundary and following-upload frames, rebuild stages, geometry, textures, heap, programs, registry truth, and RNG truth. Require at most +12 draws, no more than the pinned triangle caps, no repeatable parked p95 increase over 1ms, no FarField-attributable boundary breach of the combined tier wall, stable resource/program plateaus, and the existing absolute tier budgets of low 80/150k, mid 200/400k, and high 400/1.2M (`council-profiler.md:36-39,49`; `AGENTS.md:223-228`).

### Change Group 4: Polish, Promotion, and Project Hygiene
**Scope**: Tune only inside the proven envelope, make the promotion decision from hard evidence, and leave the OpenSpec and repository records coherent.
**Estimated Effort**: 1-2 focused sittings.
**Tasks**:
1. Apply final color, density, radius, and semantic-composition tuning from the Noon/Midnight captures without adding new visual categories. Rerun the affected deterministic, culling, visual, and performance gates after any tuning change (`design.md:115-128,147-163`).
2. Update `README.md`, `ARCHITECTURE.md`, `DEBUGGING.md`, and the relevant performance and pooling documentation with the shipped ownership model, inspection flow, limitations, and measured per-tier totals (`tasks.md:74-78`).
3. Enable the horizon by default only if every hard gate passes on every tier, while retaining `?farField=0` for one-variable diagnostics, then rerun the complete gate suite. If any tier exceeds its absolute or marginal budget, or any lifecycle or portability gate fails, keep the default off, record the failed gate, and leave the ROADMAP item parked. Update CHANGELOG and remove or narrow the ROADMAP item only according to that result, preserving the deferred real-iPhone Wook Trip capture (`design.md:167-176`; `tasks.md:66-81`).
4. Refresh the OpenSpec README and session status, record the accepted council decisions, run the final checks, stop every task-created server and browser session, and audit the exact recorded browser, GPU, daemon, and server PIDs before handoff (`tasks.md:82-84`).

## Final Recommendation
**Proceed with mitigations.** Start Change Group 1 now, but do not begin renderer integration until the OpenSpec artifacts encode the v2-only gate, immutable descriptor boundary, centralized owner lookup, shared streaming deadline, versioned pending work, and exact tier budgets. The render-only peer is structurally sound after those amendments, while default promotion remains a later evidence-based decision.

## Convergence Points

-   All three require contract and scheduling amendments before renderer integration: one owner-cell source of truth, narrow loaded-state observation, and one combined streaming wall that gives real chunks priority (`council-architect.md:5,13-15`; `council-profiler.md:7,10`; `council-adversary.md:5-7,16,18`).
-   All three support fixed-capacity opaque batches with no registry, collision, crowd, audio, real-light, or shadow ownership, plus explicit rewrite, bounds, and disposal invariants (`council-architect.md:7-8,21,25`; `council-profiler.md:8-9,15-17`; `council-adversary.md:8,19,22`).
-   All three require deterministic focused tests and a cheap isolated harness before relying on full-game driving, followed by real low/mid/high boot and lifecycle verification (`council-architect.md:6,9`; `council-profiler.md:5-11`; `council-adversary.md:6-10`).
-   All three agree that promotion is conditional on measured visual value, stable resources and shader programs, clean chunk handoff, and no meaningful performance regression (`council-architect.md:9`; `council-profiler.md:11,49`; `council-adversary.md:10`).
