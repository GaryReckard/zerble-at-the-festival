## Profiler's Position

TL/DR: Proceed with mitigations. Two shared texture tiles and a material choice per existing road ribbon should add no road draws, lights or shadow casters, but widening terrain-clipped ribbons can increase construction work and exhaust the distant road buffer sooner. Make those two costs explicit in the acceptance evidence before calling the change performance-safe.

### Priority Sequence

1. Extend Task 1.2 (production-backed surface fixture) to record the existing road mesh count, post-drape vertices/indices, texture count, cold construction time and distant `roadsClipped`, using identical seeds, locations and tier settings before and after. Start with renderer counters, then verify unchanged shadow/pass policy, consistent with `.claude/rules/performance.md:83-97`; Task 4.2 (tier and game verification) currently requests counters and cold allocations but does not specify the clipping or construction-time observations (`openspec/changes/road-surfaces/tasks.md:16`).
2. Implement whole-edge metadata and select exactly one surface material for each existing ribbon, while retaining the distant renderer's single mesh. The draft already makes this choice (`openspec/changes/road-surfaces/design.md:13-17`), and the existing detailed builder creates one mesh per clipped run (`src/chunks.js:1018-1029`). Keep grain, patches and stones inside the color texture rather than adding detail meshes or layered transparent road decals.
3. Keep texture/material counts fixed at two shared surface variants and derive UVs from the final terrain-clipped vertex positions. Reuse the existing terrain split once, then add the UV attribute; the geometry helper already performs draping before normals and bounds (`src/chunks.js:866-876`). Verify unload/revisit identity before judging steady-state FPS because resource recompilation is a separate failure mode (`.claude/rules/performance.md:92`, `src/chunks.js:587-594`).
4. Compare matched Low/Mid cart-height Noon/Midnight frames and a bounded streaming/revisit route, preserving the actual tier configuration and quality level. Current Low uses a 1.25 pixel-ratio cap, not the historical 1.0 guidance (`src/perf.js:100`, `ARCHITECTURE.md:576`), and only High uses MSAA (`src/main.js:274-282`). Keep material construction through the shim; its Low Lambert path accepts `map` (`src/threeShim.js:30`, `src/threeShim.js:57-65`).

### Budget Estimate

- **Draw delta**: Expected **+0 road draws** at identical visibility if the planned single-material replacement is followed, with the distant roads remaining one draw. Existing detailed roads already cost one draw per clipped run, so two material variants do not inherently double them (`src/chunks.js:1018-1029`, `src/farField.js:706-725`). Clearance-driven venue changes may alter total scene counters, so report those separately from the road-only delta (`openspec/changes/road-surfaces/design.md:29`). Low has the tightest nominal ceiling at 80 draws, versus Mid 200 and High 400 (`src/debug.js:35-46`); actual headroom is not established by this planning review.
- **Triangle delta**: **+0 for texturing/UVs alone**, and zero change from width alone when terrain draping is disabled. With draping enabled, the wider surface changes the grid intersections, so the triangle delta requires fixture measurements rather than a zero-cost claim (`src/chunks.js:866-876`, `src/worldgen/terrain.js:154-197`). Paved surface area rises by about **28.6% per widened edge** from 7m to 9m, excluding joints; that is an area estimate, not a triangle or FPS multiplier (`openspec/changes/road-surfaces/design.md:13`). Distant index capacity remains 6,144, or at most **2,048 road triangles**, at every tier (`src/perf.js:166,198,228`); increased clipping can consume that fixed allocation sooner. Nominal total scene limits remain Low 150k, Mid 400k and High 1.2M triangles (`src/debug.js:35-46`).
- **Resource delta**: Recommended two 512×512 RGBA8 tiles require about **2.67 MiB of GPU texels including full mip chains**, plus **2 MiB of retained base-level typed-array data**, excluding driver overhead. This is an estimate from two tiles × 512² × four bytes, with a 4/3 mip factor, not a measurement or a size already fixed by the draft. UV attributes add **8 bytes per final detailed-road vertex** if stored as two Float32 values. A fixed RGB Float32 distant color attribute adds **48 KiB** at the existing 4,096-vertex cap (`src/farField.js:709-714`, `src/perf.js:166`). Shared materials bound allocation but do not eliminate texture sampling work.
- **Cost type**: **Both allocation stalls and steady-state FPS**, with the principal new allocation risks at first texture use and terrain-clipped construction, and steady-state work from road texture sampling and wider visible coverage. The draft adds no per-frame CPU animation, lights, post-process passes or shadow casters (`openspec/changes/road-surfaces/design.md:15`).
- **Low/mid-tier verdict**: **Needs pooling and bounded acceptance evidence**, both already compatible with the design. Do not require broad instancing or geometry merging for unique clipped ribbons without a measured reason; the existing far-field batching is the valuable contract to preserve (`src/farField.js:706-725`). HUD limits remain comparison guides because current policy explicitly says they need recalibration (`.claude/rules/performance.md:48-51`), and `AGENTS.md:66-70` requires a measured baseline and device evidence rather than counters alone.

### Evidence and Acceptance Boundaries

The requested `.Codex` performance files no longer exist at those paths; their `.claude` counterparts were read, including both historical shipped-pass plans. Current source and current AGENTS instructions take precedence over their older numerical advice. The historical 115-to-56 shadow audit is a shipped optimization reference, not a fresh count of the current streamed scene (`.claude/perf-audit-plan.md`, “What shipped”; `.claude/rules/performance.md:91`).

Add bounded acceptance observations to Task 4.2 (tier and game verification): identical fixture inputs and active quality level, stable two-surface resource identities across unload/revisit, no increase in road mesh count, reported post-drape geometry deltas and `roadsClipped`, cold-versus-warm construction durations, and matched Low/Mid Noon/Midnight views. Retain the specific terrain-crease seed regression already required by the road-surface spec (`openspec/changes/road-surfaces/specs/road-surfaces/spec.md:24-29`). If the widened road consumes more distant capacity, characterize the lost edge before changing capacity; do not trade the existing fixed memory bound for an unmeasured visual fix.

This position is a source-backed plan review. No browser, device FPS measurement or runtime test was performed, and no source or other council position was edited.

### Verdict

- **Verdict**: Proceed with mitigations
- **Key Concern**: Wider terrain-conforming ribbons can increase synchronous clipping cost and omit distant roads sooner despite an unchanged draw count.
- **Recommendation**: Keep the two shared color textures, one material per detailed run and one distant draw, then make clipping capacity, construction time and streaming resource identity explicit acceptance observations. The plan does not need a new renderer architecture or an unrelated performance pass.
