## Architect's Position

TL/DR: Proceed with mitigations. The proposed boundary is sound: the pure road generator owns surface and width, while rendering owns textures and geometry. Tighten the clearance contract and explicitly preserve the narrower far-field underlay before implementing the wider roads.

### Priority Sequence

1. **Freeze the existing substrate and define the descriptor.** Record canonical edge keys and route points across representative seeds, then derive `surface` and visible `width` from the two endpoint ranks without consuming randomness. Keep the existing polyline API compatible, and carry one descriptor through bounds, approach, nearest-point and region queries. Endpoint ranks already exist in `src/worldgen/hearts.js:38`, and canonical orientation and pair-seeded route generation live in `src/worldgen/roads.js:171`. Keep the broad `onRoad`/`noBuild` corridor and existing point-query fields unchanged, as required by `ARCHITECTURE.md:228` and `ARCHITECTURE.md:247`.
2. **Resolve clearance before widening geometry.** Make shape checks use each candidate road's visible half-width plus the appropriate shoulder, then audit tree, vendor, food-court and camping placement. `shapesClearOfRoads` currently applies one global margin (`src/worldgen/roads.js:359`), while tree scatter, vendor booths and woodland households independently use fixed widths (`src/chunks.js:1100`, `src/chunks.js:1657`, `src/woodlandCamping.js:41`). Add mixed-width proximity fixtures, not just isolated paved-road fixtures.
3. **Integrate renderer-owned resources into existing ownership.** Put the texture/material helper outside the pure `worldgen/` dependency graph, create its two shared finishes lazily, and generate world-space UVs from final terrain-clipped vertices. Preserve chunk-owned ribbon geometry, chunk-keyed path attractors and the separate FarField instance. Those owners are established in `src/chunks.js:863`, `src/chunks.js:1018`, `src/chunks.js:1055` and `ARCHITECTURE.md:265`.
4. **Extend snapshots and fixed buffers together.** Copy width and surface into FarField-owned records, carry them through expansion and sorting, and populate colors for every final draped vertex while retaining whole-road overflow rejection. Current records copy only the polyline (`src/farField.js:795`), expansion retains only `flat` (`src/farField.js:307`), and terrain clipping adds vertices after initial ribbon construction (`src/farField.js:978`).
5. **Prove the shared contract through production consumers.** Run route/query-order/seed-restoration fixtures, unload and revisit checks, the terrain-crease reproduction, all five importmap checks, and the planned Low/Mid Noon/Midnight captures followed by a real game boot. The five-page requirement is explicit in `.claude/rules/no-build.md:19`; visual and integration requirements are explicit in `AGENTS.md:58` and `AGENTS.md:65`.

### Structural Risks Identified

- **Nearest centerline is not sufficient for variable-width clearance.** `nearestRoad` minimizes centerline distance (`src/worldgen/roads.js:303`), and several builders compare only its returned distance with a constant (`src/chunks.js:1657`, `src/chunks.js:1764`, `src/woodlandCamping.js:41`). With different widths, a slightly farther paved road can intrude even when the nearest dirt road clears. Preserve nearest-centerline semantics for orientation and compatibility, but use an all-candidate shape test or a dedicated minimum-clearance query for occupancy. A fixture should place a shape between nearby seven- and nine-metre roads and check both corridors.

- **The proposed width agreement needs an explicit underlay exception.** The draft specification says the detailed and distant renderers consume the same planned width, but the current distant ribbon deliberately renders at `0.8` of the authoritative width (`src/farField.js:63`, `src/farField.js:910`; `ARCHITECTURE.md:279`). Both renderers should consume the same descriptor, with the distant renderer applying its documented coverage fraction. State this explicitly rather than making the underlay nine metres wide and risking exposed dark borders.

- **Surface metadata can disappear or depend on query history.** Approach results currently contain no surface fields (`src/worldgen/roads.js:116`), nearby-road caches hold bare polylines (`src/worldgen/roads.js:291`), bounds queries construct fresh wrappers (`src/worldgen/roads.js:349`), and FarField reduces wrappers to copied arrays (`src/farField.js:798`). Define a single pure classification path and preserve existing seed/epoch invalidation (`src/worldgen/roads.js:239`, `src/worldgen/roads.js:275`). Do not attach consumer state to shared memoized arrays; FarField's copy boundary is an architectural contract (`ARCHITECTURE.md:268`).

- **Surface data must not reverse the dependency direction.** `festival.js` already imports road queries (`src/worldgen/festival.js:48`), so asking the festival planner to classify an edge would create a dependency cycle. The proposed endpoint-rank rule avoids that problem because `roads.js` already imports `heartInCell` (`src/worldgen/roads.js:15`). Keep semantic descriptors free of Three.js objects and texture references, consistent with the pure-data boundary in `ARCHITECTURE.md:228`.

- **Terrain clipping changes attribute cardinality.** Detailed ribbon geometry calls `drapeTerrainTriangles` before final buffers are installed (`src/chunks.js:866`), and the distant renderer similarly replaces vertex/index arrays after generating each ribbon (`src/farField.js:978`). Generate UVs from final X/Z positions and fill the far-field color attribute over the final committed vertex span, including every vertex introduced by clipping. Otherwise texture seams or missing surface colors can appear at terrain creases even when the original ribbon attributes were correct.

- **Full-width water safety is stronger than current route validation.** The road generator samples water along centerline segments (`src/worldgen/roads.js:123`) and retains that route when dry (`src/worldgen/roads.js:196`), which does not prove that an expanded ribbon clears the shore. The draft's water-edge acceptance needs an explicit ribbon-versus-shore fixture. If a preserved route cannot support nine metres, define and document a deterministic local width treatment before claiming both unchanged routes and complete water clearance; do not silently reroute edges or alter lake ownership to satisfy a rendering requirement.

- **Shared finish ownership must remain separate from disposable geometry.** Chunk teardown disposes non-shared geometry/materials (`src/chunks.js:587`), while the existing road material is lazy and shared (`src/chunks.js:896`). Retain that pattern for both finishes and shared-tag textures as proposed, with an unload/revisit check that observes resource reuse. FarField buffers and materials remain instance-owned and disposed by its own `dispose()` (`src/farField.js:1104`), rather than becoming chunk resources. Roads remain passable, path attractors retain `chunkKey` and zero footprint (`src/chunks.js:1055`), and the rendering change introduces no new collider or registry lifecycle.

### Verdict

- **Verdict**: Proceed with mitigations.
- **Key Concern**: A single nearest-centerline result cannot establish clearance against multiple roads with different widths.
- **Recommendation**: Retain the proposed pure semantic descriptor and renderer-owned shared textures, but make mixed-width clearance, the narrower underlay exception, copied snapshot metadata and final-vertex attributes explicit acceptance conditions. These changes fit the existing architecture without adding a lifecycle manager, animation loop or physics responsibility.
