## Architect's Position

### Priority Sequence

1. Test an exact support-query fast path first, behind the current per-mover binding, because it addresses a measured repeated operation without transferring person identity, movement authority or scheduling to another owner (`src/landscape/support.js:125-165`, `src/landscape/peopleAdapter.js:8-35`; saved High/Low profiles, `inclusive` entries for `propose`).
2. Test owner-scoped static presentation separately, because renderer traversal is substantial but the current topology snapshot does not establish static eligibility or submitted draws (`high-route-all-functions.json`, `self` entries for `updateMatrixWorld` and `projectObject`; `low-scene-topology-summary.json:1-8`).
3. Retain explicit registry publication as the bounded fallback, preserving the current vehicle-before-spatial-before-adult barrier rather than moving spatial synchronization opportunistically (`src/main.js:1463-1472`).

### Structural Risks Identified

- **Support identities are not permanent geometric certificates.** `sampleSelected` rechecks the world and resolves the selected deck, while missing support explicitly blocks movement. Any reusable region must validate the world/owner generation and surface identity before use, and must prove the entire swept footprint rather than merely caching the endpoint (`src/landscape/support.js:82-96`, `147-165`, `198-204`).
- **A presentation tile cannot become a gameplay lifecycle owner.** Chunk removal disposes owned scene resources and removes registry entries by key; lakes remain independently owned and omit `chunkKey`. A rendering service should receive removable owner contributions without moving registry/collision/support ownership into the render grid (`src/chunks.js:586-610`; `ARCHITECTURE.md:215-222`).
- **Explicit publication must replace a real mutation contract.** The registry currently observes live positions, footprint classes and collider existence, and recomputes query pads and oversized ordering. Updating only cell membership misses radius changes and removal of the maximum-radius entry (`src/registry.js:305-334`).

- **Cross-owner batches need explicit removal and resource ownership.** Chunk teardown traverses its subtree, skipping shared geometries/materials and disposing instance buffers. If presentation buffers live outside that subtree, the contributor needs its own detach handle; the batch service must release only its own GPU allocations. Shared tags alone do not define contribution lifetime (`src/chunks.js:586-610`; `src/people/childPresentation.js:109-114`).
- **Simulation and display cannot share a new visibility gate.** Current child presentation updates current instances for every active camera and keeps shadow casters when necessary. Gameplay state and collision must continue under the existing owner even when presentation is culled (`src/people/childPresentation.js:23-25`, `87-105`; `src/people/children.js:460-466`). Models must keep their origin-anchored Group and existing central animation contract, while a presentation adapter can consume their output (`openspec/specs/models/spec.md`, buildX returns an origin-anchored Group and Animatables driven by a central updater).
- **Staging cannot advertise partial readiness.** A rewrite of ordinary construction must preserve the completed-content meaning of `isLoaded`, immediate registry visibility where generation guards rely on it, and independent lake colliders. Yielding after arbitrary builder calls is therefore not a complete solution (`src/chunks.js:332-343`; `src/registry.js:54-59`; `ARCHITECTURE.md:215-222`).

### Current Contract and Scope

The evidence and current project instructions establish an approved Vite workflow, despite historical no-build/importmap wording in the config and protocol. This position requests no toolchain change and no HTML inventories; Three stays pinned behind its existing shim (`.claude/rules/no-build.md:3-5`, `14-28`). It also treats chunk unloading as current behavior, rather than the older never-unload description (`src/chunks.js:401-405`).

Scope includes adult and independent-population support consumers, ordinary chunks, forests, lakes, modern landscape owners and child display, because the candidate mechanisms cross those boundaries. It excludes changes to people behavior, scheduling, terrain resolution, collision truth, density and physics cadence. Those remain independent authorities: population owners call the support adapter at their existing publication boundary, and landscape owns support residency/leases (`src/landscape/peopleAdapter.js:8-10`, `25-35`; `ARCHITECTURE.md:973-993`, `1000-1022`). Existing adult and child batching, terrain planes, incremental registry membership and district workers are baselines, not newly claimed work (`candidate-inventory.md`, Existing work that must not be proposed as new).

### Ranked Candidates

The former has a narrow existing authority boundary and substantial measured repeated work; the latter has substantial renderer attribution but no established eligible static workload. This is an experiment ranking, not a claim of frame-rate improvement. The evidence root below is `verification/performance/2026-11-07-structural-options/`.

### Smallest Discriminating Experiments

The orchestrator should run these sequentially and keep the November 6 verified dirty source as the exact baseline. The existing lattice report demonstrates why an operation-level CPU reduction is insufficient: its 56% reduction in warm ground CPU work produced no detectable primary frame-delivery change (`verification/performance/2026-11-06-terrain-sampling/lattice-README.md`, Real production-ground CPU experiment and Runtime comparison).

1. **Support opportunity and equivalence probe.** Record a bounded copied trace at the existing `move`/`propose` boundaries, including surface identity, source/target pose, sweep/turn step counts, footprint points, returned height/gradient and block reason. Count runs whose complete swept footprint stays within one immutable terrain triangle or one live deck interior, plus all boundary/fallback cases. Then replay one exact geometric fast path against the unchanged implementation. Include rotated footprints, triangle edges, negative coordinates, approach transitions, water/grade boundaries, missing owners and world-generation changes. Require identical accept/reject, selected surface, height and published movement; do not accept a visual tolerance that changes support truth. This is the smallest test of both coverage and correctness because the current acceptance algorithm is explicitly stepwise and support-aware (`src/landscape/support.js:82-119`, `138-190`; `src/landscape/runtime.js:26-27`). Advance only if useful hit rate remains after all invalidation and certificate costs. If hits are scarce, or the theorem requires widening accepted movement, reject the candidate.
2. **One static-family presentation probe.** First inventory the snapshot's eligible records by actual owner, shared geometry/material identity, mutable/animated ancestry, render state and camera layers. Use one meaningful owner-scoped repeated family, leaving registry entries, support and animation lists unchanged. Compare removal of original traversal against a bounded spatial batch or static island in the real render path, including construction, GPU upload and disposal costs. Exercise Noon/Midnight, Low/High, all game cameras and manually moved cameras; retain offscreen shadow casters where required. Compare submitted draws, triangles, CPU work and real delivered frames, because the existing child implementation already needs per-camera culling and distinct caster handling (`low-scene-topology-summary.json:2-7`; `src/people/childPresentation.js:85-105`). Reject if acceptable batches require retaining the original traversal, increase GPU cost, or cannot cleanly detach one owner.
3. **Registry publication prototype if the first two fail, or as a separate cheap discriminator.** Count static entries versus actual frame mutations, then implement a disposable comparison path for explicit publication at the current spatial barrier. Keep the legacy scan as a shadow oracle. Verify cell/order output, same-pass add/remove, footprint threshold crossings, collider/radius mutation, moved-before-remove and deletion of a maximum-radius entry. Compare total publication plus aggregate-maintenance cost against the existing scan, rather than timing only dirty-entry processing (`src/registry.js:54-71`, `305-350`; `src/main.js:1463-1472`). Unknown writers invalidate this option until they are owned explicitly.

Only the winner of the discriminator should receive full paired hardware captures with the existing accepted comparison methodology. Profiling attribution, child maximum pass count and the unculled topology snapshot cannot substitute for that gate (`candidate-inventory.md`, Observed baseline; `low-scene-topology-summary.json:7`; lattice report, Runtime comparison). No browser, server, benchmark or production implementation was launched for this position.

### Verdict

- **Verdict**: Proceed with mitigations.
- **Key Concern**: A faster representation must not acquire authority over support truth, gameplay lifetimes or frame publication order.
- **Recommendation**: Authorize the exact-support discriminator first and an independent single-family static-presentation probe second. Select a production restructuring only after equivalence and actual delivered-frame evidence; otherwise recommend no broad rewrite and evaluate the bounded registry alternative.
