## The Adversary's Position

### Priority Sequence

1. Establish worker handshake/error handling and exact seed/world-mode identity in the harness before adding it to the live boot path. Current geographic queries are synchronous and worker modules have their own RNG state (`src/worldgen/index.js:36`, `src/worldgen/index.js:45`, `src/rng.js:37`).
2. Test discovery persistence after delayed loads, resets, quota/open failures and tab suspension, then verify the same-world restore path. Keep all persistence and worker startup outside the synchronous audio gesture chain (`src/sound.js:271`, `src/sound.js:295`, `src/sound.js:311`, `src/sound.js:327`).
3. Integrate input actions and touch ownership without modal input clearing, then test compact/expanded transitions with held controls and actual game boot. The existing combined keyboard/touch music action must move together (`src/input.js:81`, `src/input.js:88`, `src/main.js:1235`).
4. Exercise stale replies, missing actors, chunk unload/reload, hidden-tab ticks and BFCache restoration before claiming lifecycle completion. Hidden tabs continue scheduling gameplay (`src/main.js:1810`), so an independent map RAF is insufficient as a discovery clock.

### Vulnerabilities Found

- **Worker state can silently describe a different world**: A new worker starts with independent module state; its seed must be the already resolved numeric session seed, not a newly randomized or differently hashed raw input. Include world/layout identity in every request and response, ignore stale epochs, and account for mutable generator configuration when used by fixtures. `queryRegion` reads module-global generator state (`src/worldgen/index.js:45`, `src/worldgen/index.js:82`), `CONFIG` is mutable (`src/worldgen/constants.js:2`, `src/worldgen/constants.js:47`), and main resolves numeric versus string input explicitly (`src/main.js:230`). Test negative numeric and string URL seeds against main-thread geographic results. Severity: High.

- **Worker failure must not become title-card failure**: The design selects a worker but leaves constructor failure, module import errors and a missing reply unspecified. Keep map initialization optional to core game start, catch synchronous worker construction failure, handle error/messageerror, and bound request waits without retry loops. Preserve discovered landmarks/player/objective controls in a clearly degraded map state if geography is unavailable. Do not fall back to a large synchronous query on the gameplay thread. Verify the built worker URL under the GitHub Pages subpath: Vite deliberately uses relative base (`vite.config.mjs:15`), and additional harness HTML must enter the explicit page list (`vite.config.mjs:8`). Severity: High.

- **Persisted discovery does not automatically mean ordinary reload resumes the festival**: Main intentionally chooses a fresh random seed without a seed parameter or resume snapshot (`src/main.js:230`, `src/main.js:250`). The confirmed contract is persistence for the same seed. Document that distinction and exercise an actual same-seed restore path, rather than changing session-seed behavior incidentally to make the demo appear persistent. If normal reopening should restore the prior world, that is a separate product decision. Severity: Medium.

- **The legacy-world escape hatch can display fictional geography**: `?worldgen=0` still selects different chunk generation (`src/perf.js:69`, `src/chunks.js:429`). A v2 geographic worker cannot truthfully map that mode. Include world mode in the discovery namespace and disable unsupported procedural background explicitly, retaining actual observed landmarks if practical. Do not persist legacy exploration into v2 records. Test both modes without modifying existing world generation. Severity: Medium.

- **Suspending the map must not suspend discovery or revive stale work**: The game continues scheduling hidden-tab ticks (`src/main.js:1810`) and already distinguishes persisted pagehide from final teardown (`src/main.js:615`). Attach reveal sampling to accepted live gameplay movement, suspend only map rendering/query work when hidden, and fence worker/storage completions after dispose/reset. BFCache restore must re-enable the map without duplicating listeners. Quota failure plus bounded active memory also needs an explicit policy: if unsaved blocks cannot be persisted, do not silently evict them while claiming session-only discovery is preserved. Severity: High.

- **Expanded touch overlay is a separate input owner**: The canvas owns camera gestures (`src/touch.js:138`); driving controls own touch IDs and local handlers (`src/touch.js:114`, `src/touch.js:120`). A new overlay can change hit testing while a finger remains down. Preserve in-progress driving gestures, keep controls above the map, derive pinch distance from map-owned IDs rather than all document touches, and avoid `Input.clear()` during expansion because it resets touch state (`src/input.js:68`). Test cancel, close, zoom and orientation while holding throttle; ignore gameplay Space edges when activating focused map buttons. Severity: High.

### Verdict

- **Verdict**: Proceed with mitigations.
- **Key Concern**: Optional map work must not acquire authority over game boot, audio initialization, driving input, or the world's actual identity.
- **Recommendation**: Add explicit worker failure/identity contracts, same-seed persistence semantics, legacy-mode behavior and hidden-state discovery tests to the existing plan. Existing separation from Three.js materials and world ownership avoids the Safari namespace/shared-disposal tripwires. No existing RNG changes are required. Follow the current Vite instructions; the latest tooling adoption is a Gary-authored correction (`5211a1b`), so do not reintroduce historical importmap inventories. This is a plan review, not an implementation or performance pass.
