# Vite migration verification, October 29, 2026

[Toolchain guide](../../docs/toolchain.md) · [Verification index](../README.md)

## Decision and scope

Gary explicitly approved a minimal Vite migration to reduce agent bookkeeping,
with GitHub Actions building on pushes to main. The source tree contained 156
JavaScript modules before adding the new boot entry, and five HTML pages carried
manual module inventories. Those inventories and their checker are removed;
normal imports now drive module discovery and missing-export validation.

The game remains plain JavaScript and Three.js 0.160.0. The build includes the
five existing game/sandbox entry points and the Passport preview. Source maps
are emitted, generated output is ignored, and stable runtime asset paths remain
available. No rendering, simulation, RNG or audio initialization redesign was
part of this migration.

## Automated results

- `npm run check`: passed the full existing suite with the new toolchain tests.
  [Saved output](check.log).
- `node bin/test-toolchain.mjs`: passed real in-memory builds for six entry pages,
  automatic new-module discovery, deliberate missing-export rejection, the 2D
  map's exclusion of Three.js, bundled material-tier behavior, capture writing,
  size/name validation and loopback/origin access checks. [Output](toolchain.log).
- `npm run build`: passed with Vite 8.3.5. The final observed local build reported
  191 transformed modules and 283 ms; this is a single local observation, not a
  comparative performance benchmark. [Output](build.log).
- `npm run test:toolchain:http`: passed development and production checks. The
  latter used `/zerble-at-the-festival/`, checked all six pages and their linked
  resources, manifest icons, stable music/title assets, actual capture uploads,
  rejected cross-origin writes and inaccessible private files. All temporary
  servers close in `finally`. [Output](http.log).
- `ZERBLE_TEST_HTTP=1 python3 bin/test-perf-server`: passed desktop/phone URL,
  LAN-token, private-path and actual capture-upload checks.
- `python3 bin/playtest-perf drive --desktop --no-open --port 8878`: built and
  started successfully. A GET of its root returned a hashed `./assets/index-…js`
  entry, establishing that the guided workflow serves dist, not source HTML.
  Its server was stopped afterward.

## Deployment status and limits

The Pages API initially reported `build_type: legacy` with source `main:/`.
It was changed to `workflow`, and a read-back confirmed that setting and the
existing site URL. The new workflow checks PRs and checks/builds/HTTP-tests and
deploys main through official Pages actions with deployment-only write grants.

At the end of verification, the changes were local and uncommitted. No workflow
run or live deployment was exercised; those begin after the commit is pushed
to main.
Physical iOS/Safari audio unlock and phone rendering were not tested in this
session. Desktop muted clicks do not establish those device results.

Vite reports a chunk-size advisory for the roughly 674 kB minified shared
chunk (about 181 kB gzip). This does not fail the build and is not evidence
of a new runtime regression. Existing Node tests also emit module-type
warnings; converting the CommonJS test harness was intentionally outside this
migration. No device load-time or FPS improvement is claimed.
