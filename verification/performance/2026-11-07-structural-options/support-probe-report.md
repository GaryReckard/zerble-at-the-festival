# Exact support reuse feasibility discriminator

**TL/DR:** This conservative exact-support certificate passes the exercised correctness cases but does not earn production advancement. It replaces substantial native terrain-query work while adding cold cost and showing no stable warm timing benefit. Preserve it as negative feasibility evidence and test the separately justified competitor rather than plan this mechanism for production.

This is a disposable Node experiment, not production implementation or an accepted optimization. The source is `support-probe.mjs`, correctness results and provenance are in `support-probe-results.json`, and the separate bounded timing experiment is in `support-probe-timing.mjs` and `support-probe-timing-results.json`. No production source, package, server or browser was changed or started by this probe.

The oracle uses the actual `createSupportBinding` and `createSupportWorld` from the frozen source. The candidate extracts the complete actual binding and adds one optional provider-selection hook immediately before the original trial-state copy. It preserves the original sweep/turn limits, interpolation expression, loop and footprint sampling order, proposal/commit validation, retained fields and accepted pose. Node's strict deep comparison includes signed zero, and the harness reuses caller output objects so stale output fields remain observable.

The candidate retains one immutable triangle record per binding. Its four original lattice vertex values feed the original `triangleHeight` expression at every sample, including the original final sweep coordinates, rather than a reconstructed plane. A triangle record is usable only when a swept disk containing every contact at every intermediate rotation stays strictly inside that triangle. The implementation proves this using the disk's enclosing axis-aligned box, which is deliberately conservative near diagonals and cell edges. Each actual query separately checks containment before choosing the certified provider.

Before constructing a record, the experiment excludes every triangle intersecting any lake descriptor envelope and every landscape candidate envelope, so landscape streams and decks remain fallback. The proof depends on the actual native terrain provider and the current terrain generation key; arbitrary/custom providers and externally supplied support worlds have no fast-path capability. The second provider is itself an actual `createSupportWorld`, so normal/grade/support output publication stays authoritative. Production deck ownership is not recreated merely by knowing a plane: the experiment's native fast path has no dynamic deck provider, and any actual trace replay must report where the missing owner context prevents comparison to captured truth.

The proof requires no additional geometric detail or lower density. It skips native terrain lookup and exclusion scans inside certified triangles but retains all support loop and contact validation work. It adds a current-generation check, swept-box arithmetic, per-query triangle checks, one record per mover and cold exclusion/vertex acquisition. A failed containment proof does not construct a record; negative owner/lake certificates are not cached, so repeated excluded requests can repeatedly pay cold exclusion cost. This is an intentional conservative prototype cost, not a production recommendation.

Retention is bounded by one record per binding plus existing bounded terrain/candidate caches; there is no global certificate store. Cached vertex values are copied, so the terrain cell ring cannot mutate the certificate. Generation invalidation drops the record, and disposed/replaced worlds remain blocked through the actual world guard. Owner disposal is covered only by generic fallback cases until actual runtime owner context is available. A production design would need an explicit trusted capability boundary, exact generation/disposal lifetime, retention accounting across mover churn, and a decision about negative-certificate caching that does not add unbounded state.

The original geometric trace eligibility was an upper-bound inventory; this replay additionally establishes exact captured-result and accepted-pose agreement for all sampled rows. Reconstructing sampled before-states cannot establish continuous binding histories, unobserved acquisitions, commit windows or unsampled calls. Synthetic exact equivalence demonstrates only the exercised cases, while operation reductions and Node timings cannot establish ordinary delivered-frame improvement, Safari behavior or physical-device acceptance. The measured cold/maintenance burden and unstable warm result support the no-go decision below.

Source audit anchors: original binding sweep and accepted-state publication are in `src/landscape/support.js:138-190`; the frozen terrain interpolation and ground/water output logic are in `src/worldgen/terrain.js:192-224`; runtime generation and dynamic deck ownership are in `src/landscape/runtime.js:22-27`; native candidate lookup gates stream/deck coverage in `src/worldgen/landscapeCandidates.js:91-96,120-136`. The experiment asserts source hashes before executing (`support-probe.mjs:16-28`), proves/excludes certificate regions (`support-probe.mjs:38-63`), and retains exact per-sample terrain arithmetic (`support-probe.mjs:65-78`).


## Correctness and actual request coverage

The correctness command was `node verification/performance/2026-11-07-structural-options/support-probe.mjs --trace verification/performance/2026-11-07-structural-options/support-request-trace.json --seed 2404796662 --version 2`. All frozen source hash assertions passed. It exercised 595 acquired synthetic scenarios and 3,917 operations with zero strict result/pose differences, followed by all 11,358 captured sparse rows with zero candidate/oracle differences, zero captured-truth differences and no skipped trace rows (`support-probe-results.json`).

The synthetic corpus targets negative coordinates, cell/diagonal ties, translated and rotated footprints, sweep and turn limits, real lake and landscape-stream locations, generic grade providers, removable deck owners, disposal and world-generation changes. An invalid synthetic initial acquisition returns without incrementing the exercised scenario count, so 595 is the number actually acquired, not all attempted starting poses. This harness does not establish equivalence of rejected initial acquisitions, exhaustively classify every requested hazard outcome, or cover held-proposal commit races, arbitrary output setters/proxies, fork lifetimes or full streaming histories. Its strongest workload-specific evidence is the separate complete captured-result agreement on sampled pedestrian requests.

The trace additionally includes ready/exporting/completed rows, which are retained in the JSON phase breakdown but excluded from this measured comparison. Phase attribution may straddle a boundary by one rendered frame, as the capture states. The all-call geometric counts ignore dry-ground, lake, stream, deck and current-world exclusions; they are not certified hits. The certified rates describe every128th sampled request only and cannot be applied to all calls as a demonstrated total (`support-probe-results.json:trace.phases`, `trace.allCallPhaseCounters`, and `trace.scope`).

Each sparse row was reconstructed from its captured accepted before-state with adult cardinal contacts at radius .35 or child centre plus cardinal contacts at radius .4; negative-zero paths were restored before exact comparison. Every captured output field and accepted after-state agreed. Outputs were seeded with the captured field list because the capture does not record the entire caller-owned output object's history, so agreement on independently changed fields and the oracle/candidate comparison is established, while unobserved stale custom fields are not. No deck-owner context was needed for the sampled trace rows to agree, which does not establish owner-transition coverage beyond those rows.

Sparse reconstruction always starts with an empty certificate. For measured rows it incurred 39,617 ordinary acquisition samples, then replaced 29,683 request-time native samples, constructed 4,762 certificates with 19,048 vertex lookups, and counted a 10,052-call potential exclusion budget. Actual exclusion invocations were 10,029 because 23 landscape-owner rejections short-circuited the second lookup. It fell back on 1,240 cell-edge, 1,100 triangle-edge, 241 lake-envelope and 23 landscape-owner requests. Acquisition samples are excluded from the replacement percentage above but remain reported as actual proof overhead; sparse reconstruction does not measure the game's real acquisition rate (`support-probe-results.json:trace.phases.measuring.stats`).

## Bounded cold and warm timing

The timing command was `node verification/performance/2026-11-07-structural-options/support-probe-timing.mjs`, after the orchestrator confirmed all browser captures were terminal and no other benchmark was active. It froze 921 rows, every eighth measuring-phase sampled row in source order, in `support-probe-timing-roster.json` before collecting clocks. The trace SHA-256 is `17a1cbbfe8b0f49a7bf4bbaaed791da6e98bc80a35aa09735b96ad62df75cb0b`; the roster SHA-256 is `f0cb41be620652ca6ab48f4222749e6df05062ddd427ae1537439559adaa3aa0`. The timed probe source SHA-256 is `5417169d5f1f0b25b9a83343184273a30f8ebc6f628a37e7c166efab9174dcbd` (`support-probe-timing-results.json`).

Node v24.10.0 on Darwin arm64 ran eight trials with declared alternating oracle-first/candidate-first order. Both native terrain caches and JavaScript paths were prewarmed, so “cold” means first certificate on a fresh binding, not fresh world generation. Construction was timed separately, followed by the first proposal batch and twelve repeated warm proposal batches on the same contexts. Warm repetitions used `propose` for all rows to preserve the exact captured before/target inputs without changing accepted state. Exact outputs agreed after warmup, every first batch and every warm batch (`support-probe-timing.mjs`, `support-probe-timing-results.json:trials`).

| Batch | Oracle median | Candidate median | Median paired candidate minus oracle |
| --- | ---: | ---: | ---: |
| Construct 921 contexts | 3.115 ms | 4.113 ms | +1.013 ms |
| First 921 proposals | 3.937 ms | 4.704 ms | +0.842 ms |
| Warm 12 × 921 proposals | 44.428 ms | 44.516 ms | −0.024 ms |

The warm ranges were 41.978–47.086 ms for the oracle and 41.072–62.800 ms for the candidate. Order materially affected the paired median: oracle-first trials favored the candidate by 2.161 ms, while candidate-first trials favored the oracle by 9.778 ms. This small experiment therefore demonstrates no stable useful warm advantage, and the fresh-context/first-certificate cost is worse (`support-probe-timing-results.json:trials`; medians are straightforward calculations from the preserved eight pairs).

Every trial retained a maximum of one record per context and certified the same 590 of 921 requests; the 12 warm batches reused those 590 records 7,080 times. The candidate still paid 442 cold exclusion attempts for 34 repeatedly ineligible owner/lake requests, because negative certificates are not cached. Across the first plus twelve warm batches it made 1,032 cold attempts, 1,986 actual exclusion queries and 2,360 certificate vertex lookups, replacing 49,829 native terrain samples while leaving 45,383 request-time native samples and 4,957 acquisition samples. The raw exclusionQueries counter is 2,064 because it reserves two lookups per cold attempt before short-circuiting; subtracting 78 landscape-owner rejections gives the 1,986 actual invocations. The preserved JSON explicitly records this counter interpretation without rewriting raw values. Those counters agree across all eight trials and include the conservative generation/containment and failed-certificate maintenance work (`support-probe-timing-results.json:trials[*].candidate.stats`).

## Decision and limits

**No-go for this prototype as the selected production redesign.** Exact arithmetic and support ownership can be protected on the exercised native dry-terrain cases, but retaining all sweeps/contacts and paying the conservative certificate checks consumes the observed query reduction. The experiment has not established a useful warm benefit, and cold/first-use costs regress, so there is no basis to spend a production integration or delivered-frame comparison on this specific mechanism.

This does not prove all exact-support reuse impossible. A future proposal would need independent evidence that its capability boundary, less costly validation or bounded negative-certificate policy changes the net result while keeping the same full support oracle. It cannot claim a win merely by substituting endpoint/plane truth or deleting sweep checks. No ordinary frame, browser runtime, renderer, Safari, physical-device, long-run heap, actor-publication or fresh-world-generation timing claim follows from these Node results; the dynamic runtime deck-source scan and real owner churn were also outside the timed model. No delivered-frame optimization is accepted here.
