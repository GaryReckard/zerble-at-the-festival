# Disposable rendering discriminator author notes

The authored files are `render-install.js` and `render-worker.mjs`. They have passed Node syntax checks only; the root orchestrator owns the copied build, supervised browser run and interpretation. No production files, package changes, builds, browser launches or measurements were performed by the author for this task.

The worker requires the accepted supervisor's `config.smoke === true`, appends `structuralProbe=1` and `mute=1`, and leaves `kidBatch` unspecified unless already present in the supervisor URL. The copied bootstrap must expose the actual `createChildPresentation` function as `window.__structuralPresentation`. It performs a real ready-title gesture, rejects software WebGL or a hidden/unfocused page, records hardware/build-adjacent metadata, and waits 20 seconds before installation. This is rendering-work attribution, not a live FPS or ordinary frame acceptance run.

## Capture roster and clocks

The sequence covers third-person, first-person and top-down through native KeyV CDP events, with observed native mode transitions, plus Noon .3 and Midnight .75. Only scene setup is unpaused: the worker restores the prior mechanism, changes mode/time, allows 350 ms for real poses/lighting and freezes again. Every mechanism's entire `ABBA ABBA` sequence runs on one accepted world state without simulation between variants. Static flags are measured first, followed by vendor instances at that same frozen pose.

Each block has four untimed composer renders for shader/path warmup, then 24 manual RAF-triggered composer renders. Eight blocks across two mechanisms and six camera/time cases total 2,304 measured renders, with 96 samples per variant/view/mechanism. Every raw sample retains RAF timestamp, adjacent RAF wall interval, render work duration and `renderer.__sceneInfo` scene calls/triangles. The first wall interval is null. Source/batch/instance/layer counts, resource/program counts, construction durations and fallback states are saved per block, and the first A/B pair receives baseline/candidate screenshots for every camera/time/mechanism. Submission regressions are reported separately for each camera/time. No median-only result replaces the raw samples.

Paused `shouldRunFrame` returns false when there are no pending single steps (`src/debug.js:158-176`), so main.js skips `tickBody` at line 1219, and that path does not independently call composer.render. There is no deliberate double rendering. The game still schedules its lightweight paused callback, which remains part of RAF wall timing; work timing surrounds only the manual composer render. Whole-scene verification occurs outside timed frames, while the per-frame guard checks only pause state and the availability of scene counters.

The capture has a 150-second in-worker ceiling excluding boot and the 20-second settling period, while the root's supervisor provides the independent 240-second bound and process cleanup. Each CDP request expires after ten seconds and heartbeat output continues every second. The ceiling is checked between bounded blocks; a single block has its independent ten-second CDP bound. No retry silently discards a failed camera or fallback.

## Actual factory, unchanged ownership

Booths are discovered through `userData.evening.vendor`. Each merchant's ordinary eligible meshes are grouped by the booth's 80-metre world cell and passed to one actual factory adapter per cell. Eligibility matches the factory's rejection checks for instanced/skinned meshes, custom shadow materials, arrays, transparency and morph attributes. Every skip is counted, and the predicted geometry/material/render-state bucket count is recorded.

The factory receives `scene` as both scene and source. The installer temporarily replaces only `scene.traverse` during construction so it enumerates that cell's selected vendor records, then restores the original own-property descriptor or inherited method immediately in `finally`. It never reparents source nodes or reconstructs merchant poses. The factory itself retains its real per-camera culling, shadow-caster retention, normal/shear checks, instance uploads and onBeforeRender lifecycle (`src/people/childPresentation.js:23-116`). Factory construction duration is recorded outside render samples, including repeated constructions when the sequence re-enters the candidate.

Before a case, the installer retains every original node's local/world matrices, position/quaternion/scale, parent, visibility, layers, resources, render state and transform flags. It checks these with exact `Object.is` number comparisons, along with camera matrices and an ordered registry fingerprint. Layer zeroing is allowed only for the selected factory source meshes while its candidate is active. Disposal must restore layers, remove batch groups, preserve the scene's previous render hook, restore the original source mesh count and leave all original resources/poses intact. A disposed adapter or fallback reason fails the comparison and is retained in partial diagnostic output and cleanup events.

The emitted compact fingerprints are convenient identifiers rather than the correctness oracle; exact in-memory comparisons supply the assertion. The registry fingerprint covers ordered IDs, kind, position, footprint, chunk owner and primitive collider fields; it is not a serialization of every gameplay object. Resource counts cannot prove the absence of long-run GPU leaks or physical-device correctness.

## Static direct-mesh control and r160 force semantics

The matrix-only roster uses eligible ordinary direct child meshes of the audited booth, rather than the animated merchant hierarchy. `src/models/tent.js:170-242` establishes the direct booth meshes and resources, while `updateTent` below line 245 changes merchant transforms, material emission and bed/light visibility. The capture freezes simulation and retains those source states. Only matrixAutoUpdate and matrixWorldAutoUpdate are changed for this control, and their original values plus the prior matrixWorldNeedsUpdate flag are restored in `finally`-owned teardown.

The audit instruments selected local `updateMatrix` calls and `matrixWorld.multiplyMatrices` calls for one untimed render in each variant, then removes its wrappers before timing. Pinned r160 Object3D.updateMatrixWorld, lines 572-608, propagates force from updated ancestors even into children with matrixWorldAutoUpdate false. Therefore the probe claims only the observed reduction in local composition, never an assumed skip of world multiplication. A real temporary parent-position mutation verifies that force still changes the selected child's world matrix, performs an explicit republish, restores the parent and verifies exact original matrices after reverting. A stale-parent result is not invented; unexpected force behavior fails the audit.

## Cleanup and omissions

The worker persists partial results after every completed block. On any assertion, CDP deadline or other failure, it attempts adapter/flag/pause restoration before closing its exact owned target, then saves `diagnostic-result.json` and `worker-result.json`. The accepted external supervisor remains responsible for browser/server processes and exact-PID cleanup if the page or worker cannot run its own finally block.

The probes do not establish streaming/unload correctness, unpaused long-run material/transform mutation handling, actual production batching suitability, GPU completion times, device acceptance, thermal stability or ordinary delivered frames. Construction and repeated adapter churn are visible diagnostic costs, not an optimized production architecture. A submission or timing regression is useful negative evidence and must be preserved.
