## Gameplay verbs

- **Daily-seed challenge mode.** Parked from the festival-run-stakes brainstorm (2026-08-28): a third mode option where everyone plays the SAME world seed for the day (`seed = hash(YYYY-MM-DD)`), so the global leaderboard's daily tab compares apples to apples — same jug placements, same hub layout, same lakes. Mostly free once Festival Run + the Worker daily board exist (the seed plumbing and mode config gate are both in); the open design question is whether the daily board should *only* accept daily-seed runs.

- **Bubble upgrades, final rollout.** The first wave's eleven earnable types, persistence, menu, special stream and real unlock triggers are implemented. The grouped Gate C visual review is pending; then finish crowd charm and leaderboard headroom, performance review, and final docs according to [BUBBLE-UPGRADES-PLAN.md](../../BUBBLE-UPGRADES-PLAN.md).

- **Bubble-juice meter follow-ups.** The meter shipped (see CHANGELOG 2026-06-01) — drains while bubbling, ~3× on the G blast, **stops at empty** (NPCs frown when you're dry), Zelda-style jug **stockpile** (unlimited), rare floating jugs + the spacesuit bubble vendor (free refill w/ bubble-stream visual + "full" cue), top-left HUD gauge w/ reserve pips + amber/red low-empty border. The **"costs smiles" economy** shipped 2026-08-29 as Festival Run's vendor pricing (Just Cruisin' refills stay free). Parked refinements: (1) **Bubble-variety juice costs** — once bubble varieties ship, mega-bubbles could cost more juice and glow bubbles less. (2) **Drain + frown tuning by feel** — if either nags on a real playtest, soften them or gate behind an opt-in mode.

- **Tricks via boost + hop key.** Tap Space+Shift (or a dedicated key) mid-drive for a small 0.3s hop. Air time + bubbles in-air = bonus smiles when you land near NPCs (NPC reaction: "oooh!"). Reuses Zerble's existing arcade physics — just adds a vertical impulse and a "in-air" flag. New verb, no geometry.
- **Monk group ride quests.** Extend the passenger quest system below with a shared destination for the whole party. Preserve all-or-none boarding and completion, including the possibility that only a four-person party fits Zerble’s available seats.
- **Passenger quests.** A boarding rider sometimes has a small thought-bubble icon over their head showing where they want to go (tent, stage, food trucks, beach, hammocks, drum circle, etc. — all already in the registry). Layered indicators (compass strip, icon brightness, passenger humming, toast hints like "I can smell the food trucks!") help the player navigate. Within ~25m of the destination = thumbs-up animation + smile burst. Multi-passenger logistics emerge naturally at `MAX_PASSENGERS = 4`. Full design lives in [`.claude/passenger-quests-design.md`](../../.claude/passenger-quests-design.md) — destinations, signaling stack, indicator layers, toast bank, failure handling, build order, and open questions.
  - **"Gotta GO!" porta-potty emergency mission.** A special, urgent passenger-quest variant: a rider boards doing the pee-pee dance (visible squirm + a sweat-drop / "!!!" icon) and needs a ride to the **nearest porta-potty**, fast. A countdown adds light stakes — make it in time for a big relief + smile burst (and maybe a grateful honk), miss it and they bail out mortified (a flustered "fleeing" exit, small smile penalty, comedic toast). The porta-potty system already shipped (model + registry `porta_potty` entries + the door/occupied/stink machinery in [portaPotty.js](../../src/models/portaPotty.js) + [crowd.js](../../src/crowd.js)), so the destination, arrival detection, door-open-on-arrival, and "occupied, try the next one" logic are mostly reusable — this is largely the passenger-quest signaling stack plus a timer and the squirm animation. Ties the new sanitation prop into the mission loop.

- **Food-court dining loop — NPCs buy food at a truck, then carry it to a table to eat.** The *sit* half shipped 2026-06-16: ambient crowd NPCs now claim a picnic-table seat, walk over, and sit facing the table for a spell (the `walking_to_table` → `table_seated` states in [crowd.js](../../src/crowd.js), mirroring the hammock + porta-potty interaction machinery Gary asked it to feel like). Ambient beverage cups shipped on 2026-10-14, but do not imply a purchase or meal. The deeper loop is the wish: an NPC with the urge first walks to a **food truck** (the `food_truck` / food-court attractors are already in the registry), queues at the service window, "buys" food (a brief dwell), then carries a **handheld food prop** (a tray/cone/cup attached to the NPC like the existing held items) to a free table seat and *eats* it there — a small repeated hand-to-mouth gesture with a few smile/"mmm" beats — before clearing out. It layers onto the seat-claim system already in place; the new pieces are a `seeking_food` → `at_truck` → `walking_to_table`(carrying) → `eating` state chain, a pooled held-food model + attach point, and the truck service-window dwell (reuse the porta-potty arrival/queue pattern). Gate on a food truck **and** a free table both in reach; one pooled held-food draw per diner. This is the food-court analogue of the porta-potty interaction depth.
- **Vendor stand power-ups.** Extend `vendor_row` chunk themes with rare lemonade / pretzel / glow-stick stands. Drive by, get a 10s buff: faster bubble output, brighter eye glow, louder honk. Tiny new builders that reuse `foodTruck.js` patterns; existing food-truck attractor logic carries the trigger.

- **Physical festival: chairs, occupants, cooler, drinks and useful signs.** The current [planning handoff](../../openspec/changes/physical-festival/README.md) supersedes the earlier scripted-tumble recommendation and contains the [complete idea catalog](../../openspec/changes/physical-festival/ideas.md), [source evidence](../../openspec/changes/physical-festival/evidence.md), [design](../../openspec/changes/physical-festival/design.md), and [ordered implementation tasks](../../openspec/changes/physical-festival/tasks.md). Implementation is unstarted. The plan evaluates bounded rigid-body simulation while preserving arcade driving, batched rendering and explicit world/person ownership. It includes occupied-chair bracing/falling/recovery, the new cooler, existing NPC drinks extended to holders and dropped cups, and sparse route-aware signs that can remain fallen or flattened.
  - **Historical alternatives retained:** bespoke ballistic tumbling, a rigid-body engine, or a hybrid of the two. These remain documented in the idea catalog, but the old blanket claims that chairs are intangible, instancing conflicts with physical motion, and the project has no build step no longer describe current source. Current camp/stage differences and the Vite toolchain are cited in the evidence ledger.
